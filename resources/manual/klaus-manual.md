# Klaus 使用手册

本手册面向 Klaus 用户，描述各功能的用法、设置项含义和常见问题。Klaus 与 Klaus Cli 共用同一个引擎，Klaus iOS 通过同一账号远程控制桌面端；本手册同时覆盖三个客户端，各端专属内容集中在对应章节。手册内容独立于客户端版本持续更新。

本文由官网文档（https://klaus-ai.cn/docs）自动生成，逐页对应那里的一页。

## 什么是 Klaus

Klaus 是一款 AI 智能体应用，搭配自研引擎，有桌面应用 Klaus（macOS、Windows）、命令行 Klaus Cli 和用于远程控制桌面端的 Klaus iOS。它不只回答问题：会读取你的项目上下文，规划、搜索、修改文件、运行命令并验证结果，关键动作保留确认点。

它不是问答框。任务发生在你真实的项目目录里，本地文件、命令输出、网页资料和工具结果都是任务的输入；每一步的依据、产物和状态都可以回看。

### Klaus 怎么工作

一次完整的任务通常是这么走的：

1. **选一个工作目录**。为一个目录建项目，项目内的会话围绕真实文件和命令展开；临时问题用普通对话。工作目录决定了它的文件操作和命令默认发生在哪里。
2. **说清你要的结果**，而不是让它做某一步。可以用 `@` 引用文件，也可以直接贴截图或日志。
3. **需要先讨论时进入计划模式**。用输入框 `+` 菜单的「规划」（或快捷命令子菜单里的 `/plan`），先调研、回答关键问题，再审阅完整计划。可以在右侧编辑全文，选择「是的，实施此计划」后开始执行；工具操作仍按原权限档确认，见[计划模式](/docs/desktop/spec-mode)。
4. **执行时逐个调用工具**，写文件、跑命令这类动作按[权限规则](/docs/desktop/permission-resolution)决定是直接放行还是弹卡片问你。过程中你随时可以补一句话调整方向，不必等它停下。
5. **复核并收尾**。改动在[变更视图](/docs/desktop/workspace-git)里逐文件看，确认无误再整仓提交。跨很多轮才做完的事挂一个[目标](/docs/desktop/goals)，让它每轮结束自我审计终态是否成立。

### 三个客户端

Klaus 与 Klaus Cli 是同一个产品引擎的两个本地入口：配置、会话、记忆共用一份。Klaus iOS 不在手机上运行引擎，而是通过同一账号接入允许远程控制的桌面端。

- **Klaus**：完整工作台。项目会话、变更视图、概览面板、消息渠道、定时任务与技能市场在同一个窗口里。支持 macOS（Apple Silicon）与 Windows x64。
- **Klaus Cli**：终端原生形态。交互会话、一次性执行（`klaus exec`）、代码审查（`klaus review`）、MCP 直连（`klaus mcp call`），可以串进脚本与 CI。
- **Klaus iOS**：iPhone 上的远程客户端。查看桌面设备、项目和会话，发送消息与附件，处理确认并管理设备；详见 [Klaus iOS 概览](/docs/ios/overview)。

桌面端与 CLI 读同一批文件：用户级的配置、技能、钩子与 MCP 服务器在 `~/.klaus` 下，项目级的在 `<项目目录>/.klaus` 下。在 Klaus 里开过的项目，Klaus Cli 用 `-C` 指向同一目录就能继续。iOS 看到的是所选桌面端同步出的设备、项目和会话，不会直接读取这些本地目录。

### 账号与数据

- **一个账号**：Web 门户、Klaus、Klaus iOS 与 Klaus Cli 用同一个账号登录。账号不是用模型的前提：模型来源用你自己的 Claude、ChatGPT/Codex、Qoder 等订阅或 API Key；账号只用于好友、跨设备与手机配对这类功能，见[账号与登录](/docs/desktop/account)。
- **工作在本地**：任务围绕你选择的本地项目目录执行；文件访问、命令运行按确认与沙箱策略受控，凭据只存本机且对模型隐去。
- **可解释**：会话保留任务记录、完整计划、产物和引用；计划与目标可在右侧编辑，执行进度在对话和概览中查看。

## 在 macOS 上安装

Klaus 桌面端在 macOS 上仅支持 Apple Silicon，并以 DMG 分发。当前发布的版本号、渠道和体积以[下载页](/download)为准——那一页显示的是服务端此刻真实有的产物。

1. 从[下载页](/download)获取 DMG，文件较大时等浏览器完成校验。
2. 打开 DMG，把 Klaus 拖入应用程序目录，再从 Launchpad 或 Finder 启动。
3. 启动后直接进入工作台，不需要登录。先在「设置 → 模型来源」接上一个模型来源（自带订阅或自定义 API Key），再选择一个项目目录。Klaus 账号只用于好友协作、手机配对、反馈这类跨设备功能，用到时再在左下角用户菜单里登录，见[账号与登录](/docs/desktop/account)。

装完之后还有两件事值得先做：

- **系统授权**：信息、照片、Safari 这些连接器，以及电脑操控，都需要 macOS 的系统级权限。集中在「设置 → 系统授权」，其中照片、自动化、通知可以在这一页直接授权、立刻生效，其余几项会把你送到系统设置里自己勾，勾完需要重启 Klaus，详见[系统授权](/docs/desktop/system-permissions)。
- **更新**：应用在后台自动检查更新，不需要手动重装。更新包带签名校验，机制见[应用与更新](/docs/desktop/app-updates)。

如果你更常待在终端里，Klaus Cli 读同一套配置与会话，见 [Klaus Cli 安装](/docs/cli/install)。

## 在 Windows 上安装

Klaus 桌面端在 Windows 上以安装程序分发，需要 x64 架构、Windows 10 或更高版本。当前发布的版本号和体积以[下载页](/download)为准。

1. 从[下载页](/download)获取安装程序。
2. 双击运行完成安装。安装包目前**没有 Authenticode 发布者签名**，所以系统会提示来源未验证，确认来自 klaus-ai.cn 后继续。完整性并没有因此失守：安装包与更新策略本身是用 Minisign 签名的，更新时验签不过就装不上；只是 Windows 无法告诉你「这个发布者是谁」。
3. 启动后直接进入工作台，不需要登录。在「设置 → 模型来源」接上自带订阅或自定义 API Key，再选择一个项目目录即可开始。Klaus 账号只在用好友协作、手机配对、反馈这类跨设备功能时才需要。

与 macOS 的差异：

- 「设置 → 系统授权」那一页是 macOS 的 TCC 权限，Windows 上整页不出现（不是点进去看一句「不支持」）。
- 电脑操控两边都有，但靠的是不同的系统能力：macOS 走辅助功能 + 屏幕捕获，Windows 走 UI Automation + 桌面复制抓帧，所以两边的系统级准备工作不一样。
- 演示录制（你做一遍给它看再写成技能）目前只在 macOS 上。
- 命令执行权限在「设置 → 偏好设置 → 配置」里选择批准策略和沙箱模式，底层隔离由对应操作系统的实现执行。

需要准备或更新 Windows 沙箱时，输入区会显示提示。首次准备会请求管理员权限；如果准备失败且允许使用非管理员模式，提示中会提供继续选项。更新准备完成后，继续使用原有权限选择。准备或更新尚未完成时，聊天临时采用只读策略；这个临时状态不会改写各聊天已保存的权限选择。

Klaus Cli 在 Windows 上同样可用，装到 `%LOCALAPPDATA%\Klaus\bin`，见 [Klaus Cli 安装](/docs/cli/install)。

## 快速上手

这一页用一个真实的改动走完整条链路。假设你已经装好桌面端、并在「设置 → 模型来源」接好了一个模型来源，见[在 macOS 上安装](/docs/desktop/install-macos)或[在 Windows 上安装](/docs/desktop/install-windows)。

### 一、为项目目录建一个项目

侧栏会话列表里的「项目」那一段，或者在输入框上方那一行「运行于」里选一个真实的工作目录。项目是为一个工作目录建立的容器，项目内的会话围绕真实文件和命令展开；不挂项目的普通对话单独管理。

会话的工作目录决定了 Klaus 的文件操作和命令默认在哪里发生，所以这一步选对目录比什么都重要。

### 二、把目标说清楚，让它先出计划

在输入框里描述你要的结果，而不是让它做某一步。需要先确定方案时，打开输入框 `+` 菜单的「计划」再提交任务，例如「为这个项目增加 CSV 导出，并说明验收方法」。Klaus 先探索代码，再按需要用问题卡片询问关键取舍；选中答案后明确提交。

完整计划会单独显示。展开阅读，或打开右侧计划编辑器修改全文并保存；有冲突时先处理冲突。计划不合适就选「其他」说明需要修改的地方；认可后选「是的，实施此计划」（⌘/Ctrl+Enter）。它会使用当前完整版本开始实现，并继续遵守原来的工具权限。详见[计划模式](/docs/desktop/spec-mode)。

### 三、动手时按权限卡片放行

执行写文件、运行命令这类动作前会弹权限卡片，按钮是拒绝 / 允许，中间还有一档「本会话内允许」（只在引擎能从这次调用推导出一条安全规则时出现）；卡上另有一个可勾选的规则建议，勾上再放行就等于「以后同类不再问」。嫌确认太烦就去「设置 → 预授权规则」预先配好放行与拒绝的规则，或者把输入框旁边的权限档改成「自动编辑」，见[计划模式与权限确认](/docs/desktop/plan-and-permission)。

### 四、在变更视图核对改动

右侧的变更视图（界面上就叫「变更」）算的是这个仓库目前相对 HEAD 的全部未提交改动，包括未跟踪的新文件，也包括你自己手改的东西。所以它是「现在这个仓库跟 HEAD 差了什么」，不是「Klaus 改了什么」。

先看文件级统计定位范围，再展开单个文件看具体行。

### 五、提交

在变更视图提交。提交是整仓提交：先全量暂存再 commit，没有只提交部分文件的选项，所以提交前先在变更列表里确认没有多带东西。提交信息可以让 Klaus 读着 diff 写一句。

### 接下来

- 一件事要跨很多轮才做完，给会话挂一个「目标」让它自我审计终态，见[目标与侧任务](/docs/desktop/goals)。
- 想让改动落在独立分支上互不干扰，用并行工作树，见[并行工作树](/docs/desktop/worktrees)。
- 要它按时间自己跑起来，见[定时任务](/docs/desktop/cron)。
- 想教它一套你自己的做法，见[技能](/docs/desktop/skills)。

## 账号与登录

- 直接进入：应用启动即进入工作台，不需要登录。所有模型来源（自带订阅、自定义 API Key）都不要求 Klaus 账号。
- Klaus 账号：用于[好友协作](/docs/desktop/friends)、团队协作、跨设备会话、手机配对与反馈这些需要跨设备身份的功能。在左下角用户菜单里选择「登录」，走浏览器授权后回到应用；未登录时这些功能不可用，其余功能不受影响。
- 个人资料页：点击侧栏头像打开，展示累计 Token 数、Token 使用峰值、最长任务用时、最长连续天数与当前连续天数五项真实统计，下方是「Token 活动」图，支持每天 / 每周 / 累计总量三种视图；「编辑个人资料」可以修改姓名、用户名并拖动裁剪头像。设置里的「个人资料」页打开的是同一个页面。
- 第三方订阅登录：如果你已经有 Claude、ChatGPT/Codex、Cursor、Qoder、千问办公、WorkBuddy、Antigravity、TRAE 国内版、Kiro、Kimi 的订阅，或百炼 Token Plan、MiniMax M Plan、智谱 Coding Plan、方舟 Coding Plan 的套餐，可以直接把它们接成模型来源，把已付过钱的额度用在 Klaus 里。本机已装过对应官方客户端时，Claude、Codex、Cursor、Qoder、千问办公、WorkBuddy、Antigravity、TRAE 和 Kiro 还可以直接复用本机的登录态，不必重新走一遍登录；Kimi 和几种套餐填控制台的 Key 即可。各来源怎么接入见[模型](/docs/desktop/models)。这些来源的流量和额度仍属于对应服务商账号。
- 这几套登录相互独立：退出 Klaus 账号不会退出 Claude，反之也一样。退出 Klaus 账号只影响上面那些需要账号的功能，不会删除第三方订阅凭据或自定义 API 配置。

凭据只存在本机，也不会交给模型：在对话里问「我的 API Key 是什么」，它只会告诉你配了没配，不会把密钥念出来。

## 主界面与会话

### 侧栏

侧栏分两块。上面是一列固定的入口：新建对话、扩展（折叠组，里面是连接器 / 技能 / 插件 / 快捷命令 / 智能体）、频道、定时任务、记忆、好友（见[好友协作](/docs/desktop/friends)）。下面是会话列表，分四段：

- 置顶任务：你手动置顶的会话。
- 频道：来自外部即时通讯的会话，见[频道](/docs/desktop/channels)。
- 项目：按工作目录归拢的项目，展开是该项目下的会话。为一个目录建项目，项目内的会话就围绕真实文件和命令展开；没挂项目的普通对话在下面那段单独排。工作区和每个好友的任务会话也各自成组放在这一段里。这些组可以用鼠标拖动排序，也可以按住 Alt 再按上下方向键调整，顺序会记住。
- 最近任务：其余历史会话。

四段各自可以折叠，折叠状态会记住，下次打开还是那样；折叠着的段里有活动时会显示一个徽标，所以收起来也不会漏掉正在跑的东西。选中的那条如果标题太长放不下，会自动跑马灯滚动。

会话行上还会标状态，并且**排序把「在等你」的排到前面**，优先级是 等待输入 > 未读 > 正在跑 > 空闲：

- 「需要输入」是一颗蓝色药丸——它在问你一件事（追问卡或需要你选择的问题）。点这颗药丸可以先把它**静音一分钟**，让你手头的活先做完。
- 「等待批准」是一颗绿色 chip——有一张权限卡在那儿等你放行。
- 侧栏工具栏里有一个活动视图开关，只看有动静的那些会话；配一个「跳到下一条需要处理的会话」的命令，可以一路按着往下走。
- 会话是否「正在跑」只看它自己的回合：回合结束后，即使它派出去的后台子智能体还在工作，侧栏和输入框也不再显示运行中；子智能体的进度在概览面板里看。
- 全局搜索（⌘/Ctrl+K）覆盖全部会话，包括折叠着的分段、分页没加载到的会话和好友会话。

### 会话操作

每个会话支持：重命名、置顶、导出、复制会话 ID、在新任务中继续（从当前会话分支出新会话，标记为「分支会话」）、报告问题、归档、删除。这些都在会话行右边那个 ⋯ 菜单里。已归档会话在「设置 → 已归档会话」中查看、搜索、取消归档或删除。

- 分支是快照：建立分支的那一刻把原会话的记录复制一份，之后两条线各走各的，原会话后面新增的消息不会再流进分支。原会话正在跑时会先等这一轮结束（最多 20 秒）再分支，否则分支只拿到半截对话。也可以从某条消息处分支：从你发的消息分支，只带那条消息之前的内容；从助手回复分支，带到这条回复为止的全部对话。分支继承原会话的项目与工作目录，标题沿用原会话的标题。
- **「回退」只回滚对话，不动文件**。从某条消息回退，是把对话退回到那条消息发送之前：那条消息的文字填回你的输入框，之后的消息从上下文里移除，而**磁盘上的文件保持原样**——确认弹窗里就明写着这一点。「删除之后的内容」同样只动对话。
- 想连文件一起撤，是另一个动作：**回合改动区块上的撤销键**，它专门恢复文件、不动对话。这一条依赖文件检查点，而**检查点默认是关着的**，界面上也没有这个开关（它是引擎配置里的 `checkpointing`，可以让 Klaus 帮你打开）。所以默认情况下「回退」压根不碰文件，而撤销文件也会告诉你没有可用检查点——它不是一个能把改坏的代码撤回来的撤销键，真要这么用得先把检查点开上。
- 开着的时候，快照记在一个**影子 git 仓库**里（`~/.klaus/checkpoints/<项目指纹>/`）：工作树指着你的项目，历史却落在影子仓库，所以你自己的 `.git`、分支、暂存区完全不被碰，项目本身也不需要是 git 仓库（只要机器上有 git）。恢复是破坏性的：已跟踪文件被改回去，未跟踪文件被清掉，快照之后的活儿一并没了。
- 归档不是删除：会话从侧栏移到「设置 → 已归档会话」，可以随时取消归档，也可以从已归档的会话直接分支继续。归档要求这条会话当前没有在跑；要是它还挂着后台进程，确认弹窗会多提一句「此会话仍有 N 个后台进程处于活动状态」。
- **没答的问题会回到输入框**：Klaus 在任务中问你的问题，如果你切走了还没回答，重新进入这条会话时它会重新出现在输入框上方，不用往上翻找。有些问题是可选的澄清：Klaus 先按合理的假设继续干，你可以随时回答来纠偏，也可以「跳过」或「稍后再说」，任务不会因此停下。
- **重启后正在跑的任务会自己接上**：更新重启、崩溃、你自己退出再打开，Klaus 都记得哪些会话上次退出时还有一轮没跑完，启动后自动替你点继续，不用你一条条找回来。频道消息起的会话不在这个范围里。

### 多窗口与查找

- 菜单「新建窗口」打开多个独立主窗口，每个窗口保留自己的草稿与面板布局，适合并行跟进多条任务。
- 菜单「查找」（⌘/Ctrl+F）在当前窗口的内容里查找，覆盖聊天、文件、更改和浏览器页面，带匹配计数、大小写开关与「查找上一个 / 查找下一个」；回复流式输出时结果实时刷新。它与覆盖全部会话的全局搜索（⌘/Ctrl+K）是两回事。

## 计划模式与权限确认

计划模式与权限确认解决不同的问题：前者决定现在是在讨论方案还是执行，后者决定具体工具调用能不能运行。接受计划不会绕过权限确认，改变权限档也不会替你接受计划。

- **先计划再实现**：用输入框 `+` 菜单的「计划」（或快捷命令子菜单里的 `/plan`）明确进入计划模式。Klaus 先调研、按需提问，再给出可展开、复制、下载和编辑的完整计划。选择「是，实施此计划」后才进入实现；底部反馈输入用于修改和修订。普通对话中的复杂任务可能有进度清单，是否处于计划模式以会话模式为准，见[计划模式](/docs/desktop/spec-mode)。
- **三档权限**：输入框旁的下拉提供「请求批准」「帮我批准」「完全访问权限」。「帮我批准」由独立审核智能体处理需要批准的动作，并保留当前沙箱边界；「完全访问权限」关闭普通沙箱隔离和批准提示。每个聊天保留自己的选择；修改这个聊天也会成为新聊天继承的默认，其他已有聊天不变。各类聊天运行中修改权限档，从下一次工具调用开始生效。规划模式不覆盖这份选择，退出后仍按原权限执行。
- **权限卡片**：需要确认的写文件、命令或其他工具调用会显示「拒绝 / 允许」。「本会话内允许」只在引擎能从本次调用推导出安全规则时出现。卡上的「始终允许……」建议需要你勾选并批准后才保存；客户端不会自行构造放行规则。
- **预授权规则**：在「设置 → 预授权规则」配置允许、询问或拒绝规则。拒绝规则优先，强制询问规则仍可能要求确认，包括选择「完全访问权限」时。
- **配置区**：「设置 → 偏好设置 → 配置」为新聊天统一设置默认值：批准策略（按请求 / 从不请求审批）、沙盒（只读 / 工作空间写入 / 完整访问权限）、允许网络访问、输出详细程度与推理摘要；支持「全局配置」与「项目配置」两个范围。改动写入 config.toml，也可以直接「打开 config.toml」。
- **审批审核过程可见**：开启自动审批后，聊天里会显示每条请求的审核状态（正在审核请求 / 请求已批准 / 请求已拒绝 / 审核超时）与被拒原因；最近被拒的操作可以用 `/autoreview` 菜单批准一次并重试。
- **沙箱与范围**：在「设置 → 偏好设置 → 配置」选择批准策略及「只读」「工作空间写入」「完整访问权限」沙箱模式。工作空间写入模式可单独设置命令联网权限。输入框切换「完全访问权限」需要二次确认。好友和定时任务共用普通会话的执行权限，执行位置只决定初始工作目录和默认可写目录。

完整判定顺序和只读操作的含义见[权限是怎么判的](/docs/desktop/permission-resolution)。

## 目标与侧任务

### 创建和修改目标

目标是这条会话要持续达成的结果，一条会话同时只有一个。只有你明确要求建立目标时，Klaus 才应创建；普通任务不会自动变成目标。

从输入框 `+` 菜单选择「目标」，或在快捷命令中选择 `/goal`，即可打开目标输入（底部显示「目标」胶囊）。替换当前目标时会显示确认和新目标预览，取消会保留草稿。模型不能另建一个目标覆盖未完成目标，但你可以通过明确确认的替换或编辑修改它；这种用户编辑保留已有用量和创建时间。

目标进度行在输入框上方显示。点击目标或编辑按钮打开右侧目标编辑器，查看完整内容和更新时间，使用「保存 / 还原」，或按 ⌘/Ctrl+S 保存。长文本、粘贴内容和图片可以作为目标附件保存，编辑器会读取完整目标。外部更新与保存冲突会保留草稿并提示处理，不会把旧编辑覆盖到另一个目标上。

### 状态和控制

| 状态 | 含义与操作 |
| --- | --- |
| 推进中 | 目标仍在推进；可暂停、编辑或清除。 |
| 已暂停 | 按你的要求暂停；可确认恢复、编辑或清除。 |
| 受阻 | 暂时无法继续；排除阻碍后可确认恢复、编辑或清除。 |
| 用量受限 | 模型来源的额度阻止继续；额度恢复后可确认恢复。 |
| 预算受限 | 已达到目标的 token 上限；没有普通「恢复」按钮，应先处理预算或目标，再决定后续工作。 |
| 已达成 | 必须已完成并验证目标要求；完成记录和用量保留，输入框上方的实时目标行与目标编辑器会关闭。 |

恢复暂停、受阻或用量受限的目标前会说明它将在空闲时继续工作；取消不会改变目标状态。清除目标会阻止后续自动续跑，不会删除会话记录，也不会撤销已经产生的文件改动。

模型只能报告完成、受阻，或在你明确要求时暂停；不能自行恢复、增加预算或设置用量/预算受限。模型报告受阻前，应确认同一个真实阻碍连续至少三轮仍然存在，而且没有可继续推进的工作；恢复后重新开始这项审计。最终执行错误或额度错误也可能由运行时直接停止自动工作，错误仍会显示，不能把所有停止都当成完成。

### 续跑、停止与计量

- 引擎只在安全空闲点自动续跑：目标仍在推进中、处于执行而非规划模式、没有正在运行或等待中的工作，也没有排队的用户输入。你的引导和排队消息优先；一个回合结束不等于必须立即再发一个模型请求。
- 规划期间保留目标，但不自动续跑，也不把纯规划消耗记入执行目标。查看历史或重新连接不会仅因读取状态而发送目标请求。
- 按停止会暂停活动目标并中断当前工作。恢复是显式操作；后续回调不能把已清除或替换的目标重新启动。
- token 计量为未命中缓存的输入 token 加输出 token，不重复加总 token 或推理字段。目标可以没有预算；只有你明确要求时才设置正数 token 预算。预算不是轮数，达到上限会停止继续做实质工作，不能拿预算用尽当作完成。
- 有预算的推进中或预算受限目标显示「已用 / 预算」；其他情况显示用时。活动用时持续更新，暂停或规划期间不继续累计。目标用量按实际请求和生命周期结算，完成回复应使用最终计量，而不是估算。
- 目标状态与计量由引擎持久保存，切换聊天、重新连接或重开同一会话时恢复。自动续跑仍受当前模式、权限、模型来源和目标状态约束。

### 侧任务与后台工作

- 侧任务：从当前对话岔出去的小问题，单独起一条线程去问，不打断也不污染主线。侧任务默认在**右侧面板的独立标签页**中打开，可移到左侧面板；两边分别保留输入草稿、附件和运行状态。它用的是和主对话同一套转录与输入框，答完可以关掉，也可以把它转成一条正式会话留下来。
  - 它继承父会话截至安全完成位置的上下文，以及项目、工作目录、模型与思考强度；继承内容供模型参考，不重复显示，也不会被当作侧任务的待执行指令。侧任务**没有自己的记录文件**，不会出现在最近对话里。
  - 侧任务在本次应用运行期间保留，空闲不会自动删除。关闭有已提交消息的侧任务前会提示无法恢复，可选择以后不再询问。标签显示运行中和未读回复状态；退出应用会丢弃临时侧任务。
- 运行中的任务：概览面板的「子智能体」区列出这个会话派出去的后台子智能体，每行是一个头像、任务名和状态（跑马灯显示长名字），「为什么它还在跑」「刚才那个子代理干了什么」在这里看。上下文用量不在概览面板，它是输入区旁边那个圆饼 chip。子智能体按任务命名、各有独立头像，同一会话里派出去的多个子智能体彼此分得清，身份也会记住。

## 计划模式

计划模式（Plan）适合需要先确定需求、边界和实现方案的任务。Klaus 先查看工作目录里能查到的信息，再和你讨论关键选择，最后给出完整计划。

### 开启与退出

在输入框左侧的 `+` 菜单选择「计划」（或快捷命令子菜单里的 `/plan`）切换模式。单独切换不会发送空消息，已有草稿会保留。再选一次或点击输入框里的计划徽章即可退出。

模式按会话保存，切换聊天或重新打开同一会话会恢复。运行中选择模式影响下一次请求，不会把已经发出的请求改成另一种模式。目标仍是独立的会话状态：进入规划不会清除已有目标，也不会在规划期间自动推进目标。

计划模式和「每次询问 / 自动编辑 / 跳过所有权限」是两组独立选择。规划期间可以调研、读取文件、运行用于检查的命令；它不应执行实现任务的改动。退出规划后，执行仍遵守这个聊天原有的权限规则和沙箱范围。计划编辑器保存的是 Klaus 管理的计划文档，不代表开放任意项目文件写入。

### 讨论、问题与完整计划

遇到需要你决定的取舍时，Klaus 会显示结构化问题。可在问题之间切换，查看选项说明，或选择「其他」填写答案；选中选项后仍要明确提交。问题、答案和取消状态会留在对应会话中。普通对话中的可选问题与规划期间等待回答的问题有不同的等待方式。

完整方案会作为独立的计划显示，编写时显示「正在编写计划」。它应说明结果、实现方式、错误处理、验证方法和假设。你可以展开、复制、下载 `PLAN.md`，或在右侧面板阅读排版后的完整计划。

执行阶段的进度清单是另一项能力：`update_plan` 记录待办、进行中、已完成的步骤，不是需要你审阅的完整方案，也不能代替计划模式的最终提案。

### 编辑、反馈与实施

- 展开后先显示排版后的标题、列表和表格；选择「编辑计划」后才进入源码编辑，使用「保存」或「还原」。切换计划前会先保存当前编辑；遇到版本变化或文件冲突时先处理冲突，不能把旧稿当作最新稿执行。
- 确认后选择「是，实施此计划」（也可点右侧箭头选择「按目标实施」「按编排实施」或「按并行实施」），或使用 ⌘/Ctrl+Enter。Klaus 会读取当前完整计划，核对计划身份与版本，再退出规划并开始实现。批准计划不会自动批准之后的工具操作。
- 底部「实施此计划？」区域提供实施选项，以及「否，并告诉 Klaus 应该如何做得不同」反馈输入；发送反馈会继续讨论和修订计划。反馈不授权实现；新方案准备好后会完整给出。
- 取消或按 Escape 退出当前实施请求，不会被当成批准。提交失败时保留计划和编辑内容，处理错误后可重试。

旧会话里的 Spec 文档和审阅记录仍可查看；新任务使用上面的计划流程。计划模式的入口地址保持不变，相关权限见[计划模式与权限确认](/docs/desktop/plan-and-permission)。

## 并行工作树

项目会话可以运行在独立的并行工作树中（会话标记一个「工作树」徽标），改动落在独立分支上，互不干扰。

**入口在新会话页的「运行于」选择器**：选好目标项目后，那一行是「运行于 某项目 · 本地/工作树 · 分支」，把模式切到「工作树模式」就会开一个隔离工作树。不是每条目标都能开：只有「一个在真实 git 检出里的普通文件夹、且当前有分支」才给工作树选项和一个可选分支；如果目标是一个多文件夹工作区、还没建项目、根本不是 git 检出、或者是个没有任何提交的空仓库，「工作树」这一项是灰的、写着「当前项目暂不支持」，模式回落成本地。原因很直接——多文件夹工作区里每个根是各自独立的仓库，压根没有「一个当前分支」可言。

合并现在是**你在 git 侧自己做的普通操作**，Klaus 不代劳：以前会话菜单里那个「合并回主仓」的按钮、以及它背后的合并通道都已经被整条删掉了。这么改是有意的——合并涉及冲突怎么解、合到哪条分支、要不要先提交，这些该由你在自己的 git 流程里决定，而不是让一个按钮替你拍板。工作树会话的 ⋯ 菜单里现在只剩「在 Finder 显示工作树」。

机制就是 git worktree：

- 新建时在 `~/.klaus/worktrees/<仓库名>-<时间戳>` 下 checkout 一个独立目录，并开一条 `klaus/wt-<时间戳>` 分支（可以指定基线 ref）。原仓库必须已经有至少一次提交，否则建不出来。
- 新建时可以把主仓当前的未提交改动一起带进去——「运行于」那一行里有个「包括 N 个未提交的更改」开关（默认开）：已跟踪文件的修改和删除、以及未跟踪的新文件都会复制过去，忽略文件留在原处。主仓本身原封不动，改动是复制而不是搬走。这个开关只在以当前 HEAD 为基线时生效，显式选了别的基线 ref 就不带，避免把两处状态混在一起。
- 会话的工作目录指向那个独立目录，所以这条会话的改动只落在那条分支上。
- 移除工作树是强制移除那个目录（不要这个隔离目录了就是本意），分支和提交都保留；删除工作树会话时也可以勾选一并移除工作树目录。
- 只有 `~/.klaus/worktrees` 里面的目录才算受管工作树，它是会话私有工作区，不会被当成你的项目。

## 工作区、Git 与改动

### 工作目录

每个会话有自己的工作目录，Klaus 的文件操作和命令默认就在这里发生。挂了项目的会话，工作目录就是项目目录；没挂项目的普通对话用的是这条会话自己的文件夹（`~/.klaus/sessions/<会话 id>/`）。一个会话也可以同时挂多个根目录（多根工作区），常用的组合可以存成工作区方案下次直接套用；编辑工作区时可以在文件夹对话框里一次多选几个目录并入（方案内部按 id 管理，改名不会把旧方案弄丢）。

### 文件面板

右侧的「文件」面板（⇧⌘/Ctrl+E）列出这条会话工作目录里的文件，多根工作区会列出每个根。SSH 远程项目同样可用，读的是远端的文件。

- **文件树**：按文件类型显示图标，目录点开时才加载。顶部的「筛选文件...」按名称、路径或字符顺序模糊匹配。键盘上，方向键移动和展开收起，Home / End 跳到首尾，F2 重命名，也可以右键重命名。文件树和预览区之间的分隔条可以拖动调宽，聚焦后也能用方向键调。每条会话分别记住自己的展开状态、选中文件和滚动位置。
- **单击预览，双击固定**：单击文件在一个预览标签里打开，再单击别的文件会替换它；双击文件或开始编辑后，标签就固定下来不会被替换。
- **排除列表**：「设置 → 偏好设置」最下面的工作区排除规则（每行一条 glob）决定文件树和筛选时跳过哪些路径，默认为空。搜不到本应存在的文件时先看这个列表。

### 直接编辑文件

Markdown 文件（`.md`、`.markdown`）默认用排好版的文档视图打开，也可以「查看源码」切到源码；其他可写的文本文件用源码编辑器打开。两种视图都能直接改，停止输入 3 秒后自动保存，状态显示「正在保存…」「已保存」。切换文件或视图时，光标、滚动位置和撤销记录都会保留，切换前也会先把未保存的修改存下来。

- 保存失败时草稿保留在编辑器里，显示「保存失败」并给出「重试保存」。
- 文件在你编辑期间被别的程序改了，Klaus 会暂停自动保存，提示「文件已在磁盘上更改，请选择保留的版本。」：选「使用磁盘版本」丢掉自己的修改，或「保留我的更改」覆盖磁盘上的内容。
- 二进制文件、过大被截断的文件和只读文件不能编辑；图片、音视频、PDF 这类直接用预览打开。

### 变更面板

「变更」面板看代码改了什么。顶部选「范围」：

- **分支**（默认）：从远端默认分支和当前分支的共同祖先，比较到你的工作区现在的状态，也就是这条分支整体相对主干改了什么。「比较基准」默认自动选择，也可以「指定引用」换成别的分支或提交。
- **未提交**、**未暂存**、**已暂存**：对应 git 的三种未提交状态。
- **提交**：看某一个提交的改动。
- **最近一轮**：只看上一回合 Klaus 改了什么；会话涉及多个仓库时跨仓库汇总。

会话涉及多个仓库时，可以在「仓库」里选其中一个或「所有仓库」。分支、未提交、未暂存三种范围会把未跟踪的新文件也算进去。注意变更面板看的是仓库的真实状态，**你自己手改的东西也会出现在里面**，它不是「只属于 Klaus 的改动」的清单。改动文件特别多时会只给总体统计、不展开逐个文件。

每个回合结束后，对话里还有一张这一轮的文件改动卡：头部写「已编辑 N 个文件」和增删行数，下面列出文件（多文件默认显示 3 个，可以「再显示 N 个文件」），每行带增删数。点一行跳到变更面板里这一轮的那个文件，⌘/Ctrl 点击则直接打开文件；「查看变更」打开整轮的差异。这张卡只用来看，没有撤销按钮。

### Git

- 客户端自己管列分支、切/建分支、以及切换前的未提交改动检查。更复杂的 Git 操作由 Klaus 用命令完成，走正常的权限确认；对还不是仓库的目录执行 `git init` 也属于这一类——输入框上方不会替你自动初始化，但让 Klaus 初始化是可以的，它走命令加权限确认。
- 分支只在「单文件夹项目 + 已是 git 仓库 + 有当前分支」时出现在输入框上方。选中的是多根工作区（或工作区文件）时不给分支控件——一组目录没有单一的「当前分支」；这种目标下「工作树」选项同样不可用并注明原因。空仓库（init 过还没有提交）也没有分支可选。
- 切换分支前会先查会被检出覆盖的未提交改动：只有当 git 真的会拒绝这次切换时才弹确认，列出那些文件并给你「提交并切换分支」这条路；改动能原样带过去的（不冲突的编辑）不打扰你，直接切。
- 提交是**整仓提交**：先 `git add -A` 再 commit。只有一处例外，就是上面「提交并切换分支」那一步——它只提交会被检出覆盖的那几个文件，剩下的改动照样留在工作区。提交前先在变更面板里看一眼是不是多了你不想带上的东西。提交信息可以让 Klaus 读着 diff 写一句，空信息会被拒。
- 仓库处于半途的 merge / rebase / cherry-pick / revert 状态时，Diff 和提交都直接拒——不会在一个没收尾的合并上再压一次提交。先把那个状态收尾。

## 频道（Channels）

频道页是统一消息入口，把外部即时通讯的消息接进 Klaus 处理。支持接入：飞书、钉钉、微信、企业微信、QQ、Telegram、Discord、WhatsApp。接入后来自这些渠道的会话会出现在侧栏。

每个平台的凭据（机器人 token、webhook 地址等）存在本机设置里，不会交给模型。一条消息从平台到引擎要过去重、门禁、认主、绑定上下文几步，详见[频道消息怎么进来](/docs/desktop/channel-intake)；「消息发过来了但它没理」通常是在门禁那一步被静默挡掉了。

- 门禁配置是每个平台一份文件：`~/.klaus/channels/<平台>/access.json`。**没有这个文件就等于这个平台没有门禁，来什么都处理**；文件坏了则相反，一律挡住，不会变成敞开的门。
- 私聊四档：`pairing`（默认，陌生人私聊会先收到一个配对码，你在界面上批了才通）、`allowlist`（只有名单里的人能私聊，其余静默丢弃）、`open`（谁私聊都收）、`disabled`（不收私聊）。Discord 没有 `open` 这一档，只有三档。
- `disabled` 在多数平台上只挡私聊，群消息照旧按群登记走；**只有 Discord 的 `disabled` 是连群一起挡**。
- 群聊要先登记：**没登记过的群一律丢弃**——那份文件本身就是「哪些群启用」的清单。登记后可以再给这个群加成员白名单（留空就是群里谁都行）。
- 群里**默认必须 @ 它才回**。想让它在某个群里有问必答，要显式把该群的「需要 @」关掉。
- 被挡掉的消息对发送者是完全静默的，不会回一句「你没权限」——所以从对方视角看只是「没人理」。
- 微信和 WhatsApp 靠扫码登录，这一步只能在界面里做，Klaus 代不了；Discord 另有一整套准入与投递设置（私聊策略、待批配对码、群里要不要 @、消息分段长度与回复方式），改群配置和改投递格式都是整体覆盖而不是逐字段合并。

## 定时任务

- 创建：定时任务页是「列表 + 详情」双栅：左边排任务，右边看选中那一条的排程、提示词、通知策略与运行历史。支持「表单创建」和「通过 Klaus 创建」（用自然语言让 Klaus 建任务）两种方式。让 Klaus 代建的任务**默认是启用的**，不用补一句「记得打开」；不循环的任务跑完一次就自动停用。
- 运行：按 cron 表达式调度，支持时区；频率除了自己写表达式，还有每日、每周、每月、Weekdays（工作日）这些预设；也可「立即运行」手动触发一次。每次运行产生一条运行记录。
- 模型与思考强度：任务里选的模型和思考档会被**冻进这个任务**，每次运行都用它，不跟随你在输入框里改的全局选择。这是有意的：一个每晚跑的任务不应该因为你白天换了模型就换了表现。
- 启停：每个任务可「启用/停用」。一次性任务运行完成后自动停用——是停用而不是删除，卡片、运行记录、那一轮的会话历史都还在，想再跑重新启用即可。
- 执行位置与权限：可选普通会话、项目或工作区，以及「请求批准」「帮我批准」「完全访问权限」。位置决定初始工作目录和默认可写目录，运行时共用普通会话的权限判定。新建和旧任务默认完全访问；保存其他档位后，后续运行按保存值执行。请求批准会在运行会话里等待你处理，帮我批准交给审核智能体。单次运行超时默认 5 分钟，任务自带的「超时秒数」调度器会真正采用，上限 24 小时，所以长任务可以把这个值调大。
- 通知策略两档：「只在失败时通知」（默认，跑成功不打扰你）和「每次都通知」。投递到 IM 的任务另走频道绑定。
- 投递到 IM：任务可以绑定一个频道会话，每次运行的回复直接发到那个聊天里；运行失败时发的是失败提示，不会让你以为一切正常。绑定是创建时定下的，之后改不了——要换目标就删了重建。
- 防休眠：任务页的开关。开着时 Klaus 拿住一个只防「空闲休眠」的锁，不会把屏幕点亮；关掉或退出应用就释放，重开应用会自动恢复。合盖子引起的休眠它管不了，靠定时任务过夜就别合盖。
- 排障：调度与投递日志写在 `~/.klaus/electron-host.log`，是其中 `kind` 为 `cron` 的那些行。

## 记忆与梦

Klaus 的长期记忆通过「梦」机制整理——像 REM 睡眠一样，把近期对话的线索织成长期记忆。

- 定期整理（自动做梦）：同一页的第二个开关，**默认关闭**，要先打开。打开之后，当累计 ≥ 5 个新会话且距上次整理满 24 小时，Klaus 才在后台自动做一场梦（整合一次记忆）。两个阈值都可以改，没填就用 24 小时 / 5 个会话。
- 手动触发：记忆页可「现在做一场梦」，不看上面两个阈值——但**自动做梦那个开关还是得开着**：引擎把它当总闸，关着的时候手动那一下只会答「门没开」，什么也不跑。
- 手动那一下还有三种会被拒的情形：本次启动以来没有任何一条会话真正跑完过一轮（答「没有可整理的上下文」——它不会拿一条空会话去做梦）、已经有一场梦在跑、以及另一个 Klaus 进程正占着整合锁。连上面那道总闸，这四种它都会直说原因，不会假装跑了一场。
- **一场梦开始了就没法中止**：梦跑在引擎进程里，而引擎没有给「正在整合记忆」这件事留取消入口。所以记忆页那个「叫醒它」按钮只在快照声明自己可中止时才出现，而引擎的梦一律声明 `stoppable: false`——按钮实际不会出现，硬调停止接口也只会答「没能叫醒它」。等它自己结束（通常几十秒到几分钟）即可；不想让它再自动跑，就去「设置 → 梦」关掉自动做梦。
- 往昔的梦：记忆页展示历史梦记录，包括每场梦审阅了几个会话、动了哪几份记忆、一句话摘要。
- 记忆文件：分为记忆目录、关于你、你的偏好、在做的事、相关资料几类，存放在本机 `~/.klaus/agent-memory`，可「在 Finder 打开」直接查看。
- 自动记录：「设置 → 梦」里的第一个开关（界面上叫「自动记录」），**默认关闭**。打开之后每轮对话结束就把值得保留的信息直接写进记忆（略增用量）；不开的话，记忆只在整理（做梦）时更新。
- 「设置 → 梦」有五项：自动记录、定期整理两个开关，最短间隔、最少会话变动两个阈值，以及记忆与梦的维护模型选择。没有「做梦时提炼技能」这类开关，做梦只整理记忆。

## 模型

「设置 → 模型来源」用于接入和管理每个来源的账号、端点与模型目录。「设置 → 模型档位」配置高中低档位和顾问，「设置 → 多模态模型」配置生图、生语音、生音乐和生视频。浏览设置页不会切换聊天正在使用的主模型。

Klaus 不售卖模型，也不需要会员：所有来源都使用你自己的账号或密钥，Klaus 不计量也不收取使用许可费用。存量官方会员会话在升级后显示模型不可用，改选其它来源即可继续。

| 智谱 Coding Plan | 填套餐 Key，并选对站点：国内（bigmodel.cn）或国际（z.ai），密钥不跨站使用 |
| 方舟 Coding Plan | 填套餐 Key；另外可以登录方舟控制台，用来显示 Coding Plan 额度 |

这些来源的流量和额度都属于对应服务商账号。MiniMax M Plan 的文本、图片、语音和视频共用同一份订阅额度。

**自定义 API Key** 接入你自己的模型服务。服务商可选 Anthropic、OpenAI Compatible、Kimi API、DeepSeek、Google Gemini、AWS Bedrock、Google Vertex，填 API Key、端点和模型名。几个容易漏的选项：

- OpenAI Compatible 可以选 Chat Completions 或 Responses 协议。
- Anthropic 可以选密钥放在哪个请求头：`x-api-key` 或 `Authorization: Bearer`。只认 Bearer 的网关选后者即可接入。
- 可以声明模型支持哪些推理档位、是否支持深度思考、是否能看图。声明了深度思考的千问兼容模型，聊天里的思考开关会直接控制当次回答开不开深度思考。

#### Claude 多账号与额度轮换

Claude Code 来源可以保存多个账号。已登录后，「登录 Claude 账号」和「复用本机 Claude 登录态」两个按钮仍在，用来追加账号；同一个账号重新登录只更新凭据，不会出现两条。

当前账号被限流或额度用完时，Klaus 把它移到队尾，用下一个账号重试同一个请求，你不需要手动切换。遇到认证失败时，Klaus 先尝试续期登录；仍无法认证且还有其他账号时，也会自动尝试后续账号。所有账号都尝试后仍不行才报错；只有一个账号或全部账号登录失效时，需要重新登录。各账号的剩余额度在侧栏底部的用量入口里逐个列出，并标明当前在用的是哪一个。额度查询会短暂缓存并合并同时发起的请求；额度接口暂时限流时会等待后再查询，这不表示账号额度已用尽。

### 模型档位

高、中、低档位为不同复杂度的任务配置所用模型，每档都可以选不同来源的模型。例如，高档使用 Claude 订阅，中档使用自定义 Qwen，低档使用自定义小模型，不必与聊天主模型来自同一个来源。

- 高档服务最难的任务。
- 中档服务中等难度的任务。
- 低档服务最简单的任务。

每次新建子智能体时，发起委派的主模型必须显式传入 `model`，无需用户逐次指定。在「设置 → 偏好设置 → 配置」中，「从模型目录选择子智能体模型」默认关闭：关闭时主模型按任务复杂度传 `low`、`medium` 或 `high`；开启时从统一模型目录中选择具体的 `来源:模型`。目录复用模型来源与「模型分工与编排」页面的目录，只提供已连接来源的条目，不需要手写或猜测模型 ID。开启但没有可用条目时，会提示无法新建子智能体。

缺少参数、使用 `inherit`，或在关闭开关时传具体模型，都会被拒绝。显式选择优先于角色和默认子智能体配置；传入的档位无效、模型不在目录中或当前不可用时，才自动回退到该次创建捕获的主会话模型，并记录原因。开关保存后在下一次推理步骤生效，已启动的子智能体保留原模型，使用 `followup_task` 继续。上下文压缩使用所属聊天的主模型。在「设置 → 模型分工与编排」的「子智能体档位」区域点「修改」，先选来源，再选模型并保存。选择「跟随该聊天主模型」时，该档沿用调用所属聊天的主模型；某档已配置但来源或模型当前不可用时，该次调用回退到所属聊天的主模型。同页的「编排」区域用于选择开启「编排」模式（`/orchestrate`）时的执行模型：聊天主模型负责规划和验收，这里选择的模型负责写代码和验证，默认可直接使用中档模型，也可开启「自动改用主模型」在执行模型不可用或额度耗尽时自动接力。

模型档位与聊天主模型彼此独立：修改档位不会改变输入框里选择的主模型。保存后立即返回，正在运行的聊天在后台逐个跟进新配置；新配置在下一次调用生效，已开始的请求和子代理继续使用各自开始时的配置。已退出登录、被删除、未授权或不支持任务所需能力的模型会标记为不可用；新建子智能体遇到这些选择问题时按上述规则回退，并记录回退原因。

生图、生视频、语音与顾问各是一个全局选择，不随语言模型档位变化，见[图片、视频与语音生成](/docs/desktop/media-generation)和[顾问](/docs/desktop/advisor)。跨来源调用会把相应任务内容发送给所选服务。上下文压缩会处理会话内容。

### 辅助任务模型

标题生成默认跟随所属聊天的主模型，不需要单独配置。想让标题生成固定用别的模型，在「设置 → 偏好设置 → 会话」里选择来源和模型；选回「跟随会话主模型」即恢复默认。记忆与梦的维护模型在「设置 → 梦」里选择，消息推荐模型在「设置 → 偏好设置 → 编辑器」里选择，语音识别的文字整理模型在「设置 → 语音」里选择，都和各自的开关放在一起。四项都是全局选择，对所有聊天生效，可以跨来源任选，与聊天主模型和高中低档位互不影响。

所配来源已登出、模型被删除或引用无效时，任务不会失败：标题生成、消息推荐和记忆维护自动回退到所属聊天的主模型继续运行；语音整理请求失败时保留识别原文。前三项的修改会推送给正在运行的会话，从下一次调用生效；语音整理在每次请求时读取当前选择，改完下一次听写即生效。跨来源调用会把相应任务内容发送给所选服务。

### 聊天主模型与思考强度

主模型负责直接对话和工具调用，在聊天输入框中单独选择。主模型来源、模型选择和思考强度分别保存在每个聊天中，修改一个聊天不会改变其他已有聊天；新聊天继承最近保存的默认选择。切换来源时，模型会落到该来源的默认模型上（例如 Codex 默认 GPT-6.1 Sol），之后可以再手动改。

思考强度与高、中、低模型档位不是同一项设置。可选的档位从关、低、中、高到极高、最高，具体列出哪些取决于模型声明的能力。

输入框左侧的 `+` 菜单（以及快捷命令 `/parallel`，兼容旧命令 `/ultra`）提供独立的**并行**工作模式，不再混放在思考强度菜单中。开启后底部显示「并行」胶囊，Klaus 会把复杂任务拆成多路子任务同时做，最后汇总结果；请求期间优先使用模型声明且支持的协作推理档位，否则优先选择「最高」（Max），再按模型声明的顺序选取最后一个普通档位，没有可用声明时使用中档作为请求默认值。并行模式按聊天单独保存，原来的普通思考强度选择也会保留，点击底部胶囊或再次选择该模式即可退出并恢复原档位；已有聊天的选择不会改变新聊天默认值，空白新聊天里的选择才会保存为默认值。同层级的**编排**模式（`/orchestrate`）则由聊天主模型负责规划和验收、执行模型负责写代码和验证。各工作模式与会话权限档位彼此独立，开启任何工作模式都不会改动当前权限，也不会额外弹出完整访问确认窗。

聊天进行中也可以修改模型、思考强度和全局档位。准备完成后，新配置从主回合的下一次推理步骤生效，不必等待最终回复。已经发出的请求、该请求的重试，以及已经启动的子代理、旁问、标题和维护任务继续使用各自捕获的配置；切换不会结束后台预览服务或清空聊天历史。

输入框选择器表示保存的选择。切换模型不显示准备提示，新配置由引擎在下一次推理步骤捕获生效；准备或保存失败时，输入框内显示原因。连接断开或无法确认引擎是否发布成功时，不会悄悄用旧模型继续发送。重新选择或重试会核对引擎记录后再准备最新选择。

### Codex 快速模式

使用 Codex 来源的模型时，输入框的模型菜单里多一个快速模式开关：开启后响应更快，用量也更高。模型名前的闪电图标一直显示，空心表示关、实心表示开。这个开关按聊天保存，同时作为之后新聊天的默认值；切到其他来源时它不生效，切回 Codex 时恢复原来的状态。其他来源不显示这个开关。

### 消息预测

输入框为空时会根据对话预测你可能要发的下一条消息，默认由当前会话选的那个模型生成，也可以在「设置 → 偏好设置 → 编辑器 → 消息推荐」里单独指定，任何模型来源都可以用，不需要额外的订阅或登录。按 Tab 接受，内容作为草稿填进输入框，你还可以改了再发。回合还在运行或处于计划模式时不出预测。不需要的话，在同一处关掉「显示预测内容」。

### 查看额度

侧栏底部的用量入口显示当前会话所用来源的额度：剩余量、重置时间和套餐，部分来源还分个人与组织额度，按多个时间窗口（如五小时、每周）计的来源分别显示每个窗口。显示的是你当前打开的那条会话的来源，切换会话时自动刷新；自定义 API Key 只显示模型和计费提示。

## 联网搜索

「设置 → 联网」分两块：搜索结果从哪来，以及抓网页时怎么抓。

### 搜索来源

一个总开关加一个「生效来源」下拉。**默认是 Bing**，走后台浏览器搜，不需要任何 API Key——但要求[浏览器操控](/docs/desktop/browser)那个内置插件是开着的，因为搜索就是它在跑。关掉总开关后搜索工具直接不上桌；你直接给网址时仍能抓网页，所以关掉搜索不等于断网。

可选来源：

- **Bing**（默认）：后台浏览器搜 Bing，无需 Key。连接失败或撞上验证页面时**明确报错**，不会静默换一家——这是有意的，悄悄回退会让你以为搜到的就是全部结果。
- **模型自带**：由服务商在服务端搜。需要模型本身支持（Anthropic、OpenAI 的官方模型支持）；走第三方网关或自定义 baseUrl 的不支持，这种情况会自动回退到 Bing 浏览器搜索。选这一档时客户端的搜索工具会从模型眼前撤掉，让它只看到一个搜索面。
- **订阅自带的搜索**：Claude 订阅、Codex、Cursor、Qoder、千问办公、WorkBuddy、Antigravity、TRAE 国内版、Kiro、Kimi、百炼 Token Plan、MiniMax M Plan、智谱 Coding Plan 都可以用各自账号自带的搜索服务回答搜索，不占用当前会话的模型，也不要求会话本身用的是这个来源。这些来源复用「设置 → 模型来源」里的登录凭据；没连接的来源选中时会提示先连接，用的时候凭据失效会明确报错。
- **Brave 和自定义接口已退役**：不再提供这两项的配置入口。早期版本已经配好且正在生效的旧配置会继续保留显示，但不能再被重新选择。

另外两个旋钮：**屏蔽域名**（逗号分隔，把这些域名的结果排除掉）和**最大次数**（限制每回合搜几次，防止它无限搜下去）。只允许哪些域名的白名单没有界面入口，要用的话改引擎配置。

改来源或填 Key 都是对**新会话**生效。

### 网页抓取

抓网页不随搜索来源或会话模型改变，关了搜索也照样能抓。读取的是网页返回的正文，不执行页面里的 JavaScript，也不需要另外安装浏览器。要看脚本渲染后的页面，用应用内浏览器打开。

- **阻止域名**：逗号分隔，禁止抓取这些域名。这是一道安全防护——比如把不希望被访问的私有域名写进去，就不会因为一个链接把这些站点的内容拉出来。

## 图片、视频、语音与音乐生成

生图、语音、音乐、生视频各有一个全局选择，位于**设置 → 多模态模型**。模型来源的登录状态决定哪些选项可用；真正执行时，只使用这里选中的来源。所有聊天共用这些选择——聊天用 Claude、Codex 或其他语言模型，都不会改变生成走哪个来源。

当前版本的生成只走**已接入的订阅来源**，没有自定义接口选项。每个来源用对应账号的登录凭据，不用另填后端。

生成工具始终可调用，每次请求都读取当前的选择。选中的来源未登录或请求失败时，工具会明确返回错误，不会悄悄改用其他已配置的来源。改了选择之后，后续请求就用新的，不需要更换聊天的语言模型。

聊天里的生成过程有专属展示：图片、视频、音频和音乐各带自己的图标，状态行随进度更新——从等待批准，到正在生成，再到已生成、生成失败或已停止；一条消息里的多次生成会合并为一组显示，其中任何一次失败都会如实标出。

### 各能力可选的来源

- **生图**：Codex、Cursor、Qoder、千问办公、WorkBuddy、Antigravity、TRAE 国内版、百炼 Token Plan、MiniMax M Plan。
- **语音**：Cursor、MiniMax M Plan、百炼 Token Plan、WorkBuddy。
- **音乐**：千问办公，可以附上歌词。
- **生视频**：MiniMax M Plan、WorkBuddy、千问办公、TRAE 国内版。

### 各来源的限制

- **参考图（改图）**：Codex、Cursor、Antigravity、TRAE、WorkBuddy、千问办公支持带参考图；Qoder、百炼、MiniMax 只支持文生图，不接受参考图。参考图每张上限 4 MiB，一次合计上限 8 MiB。千问办公的生图提示词上限 2500 字。
- **MiniMax 视频**需要 Explore 或 Build 档位，Go 档不支持；视频模型名保留你已设置的，但接口地址和凭据始终来自 MiniMax 订阅。
- **百炼语音**走套餐网关自己的语音合成路由，花的是套餐额度，只接受 qwen-audio-3.0 系列模型，返回一个 24 小时有效的下载链接。智谱 Coding Plan 和方舟 Coding Plan 不作为语音来源。
- **MiniMax** 的文本、图片、语音和视频共用同一份订阅额度。

每次生成语音时还可以临时指定音色、情绪和语速，不必改全局配置：音色对所有来源有效；情绪（平静、开心等）只有 MiniMax 会采用，Cursor 不接受情绪覆盖；语速范围 0.75 到 2 倍，由支持的来源采用，不支持的参数会被忽略。

本地生图、生视频、语音在当前版本不可用。保留的旧本地配置不会拦住另一个明确选中的订阅来源；选中该旧配置时会收到不可用提示。

生成的文件算这一轮的产物，落在会话目录里，在对话中直接播放，也能在文件面板中打开，见[会话产物](/docs/desktop/session-artifacts)。

## 会话产物

一条会话产出的东西不止对话文字。它们分几类，各自有各自的位置：

### 产物列表

「概览」面板里的「产物」一栏列出这条会话改过或生成的文件——网页、图片、文档、图表。点开就地预览，可以切源码与预览两种看法，也可以单独开一个窗口，或在访达里定位。想浏览整个项目目录、直接改文件，用的是另一个入口「文件」面板，见[工作区、Git 与改动](/docs/desktop/workspace-git)。

预览的范围是这条会话的工作目录（多根工作区就是它的每个根），加上你上传的文件缓存；这条会话自己写出、读过或从专用产物目录明确展示的图片，也能被预览。脚本保存的截图通过回复里的独立图片引用登记，重新打开历史聊天时会恢复。专用产物目录兼容旧的平铺图片，子目录按聊天归属检查。别的路径会明确答「超出预览范围」，命令输出里碰巧出现的字符串不算图片授权。

产物渲染在**回合折叠区之外**：即使你把这一轮的过程收起来，产出的图和页面还看得见。图片文件要是后来被清理掉了，卡片会显示一条加载失败的提示，而不是把文件名画成一张破图。

### 回复里的文件、网站与音视频

- **文件引用可以点**：回复里提到的本地文件会显示成带类型图标的文件块，可以带行号，点一下在右侧面板打开并定位到那一行。
- **网站卡片**：回复里给出的 http(s) 链接会在回复下方生成网站卡片。点「打开方式」选在哪里打开：「在 Klaus 中打开」（应用内的浏览器面板）、已安装的 Google Chrome，或「默认浏览器」，也可以「复制链接」。每次选一个目标，选过的会被记住作为下次的默认。
- **音视频内联播放**：生成或引用的音频、视频文件直接在对话里出播放器，可以播放、暂停，也能「另存副本…」，不用先去找文件。

### 就地渲染的页面与图表

Klaus 可以直接在对话流里渲染一个页面给你看，不用你去开文件：

- **内联可视化**：它把一个自包含的 HTML 页面写进这条会话专属的可视化目录，然后在回复里写一行指令，转录里就地出现一个渲染好的页面。只有这个目录里的页面会被渲染，内容在沙箱 iframe 里运行，碰不到你的其他文件。单个页面有 1 MB 上限，一条消息最多 8 个。这个能力有开关，关掉之后目录、说明和渲染一起消失。
- **图表与 3D 场景**：装了图表、3D 工作室等官方插件后，架构图、流程图、3D 场景可以直接在对话里出卡片，点开在面板里就地编辑。
- **交互 Widget**：`show_widget` 会在对话里挂一个可交互的 HTML 组件，可以整体替换也可以局部打补丁，带标题和一份传给页面的数据。它同样是沙箱化的，而且**不能替你发消息**——要发必须你确认。

### 运行预览

`run_preview` 打开一个已经在跑的 http(s) 预览地址（比如一个开发服务器），挂在后台的浏览器标签页里，不会自动抢到你眼前。它只负责打开，不负责把服务起起来；地址必须是绝对的 http/https，带凭据的 URL 会被拒。

### 界面验证截图

Klaus 改完界面并在真实运行的界面上验证后，可以把验证截图直接放进最终回复，让你看到修改后的效果。截图保留原图，可以放大查看、保存，之后翻历史也还在。

### 图片、视频、语音与 PDF

生成图片、视频和语音是另一条路：那三个工具一直在，能不能用是每次调用时按你在「默认模型」里的选择判的，见[图片、视频与语音生成](/docs/desktop/media-generation)。生成出来的文件同样落进产物列表。

PDF 由内置的 PDF 技能处理：提取文字和表格、逐页渲染检查版式与图表、生成新文档，以及拆分、合并、旋转。它用到的 Python 环境由 Klaus 在第一次使用时自动准备，不需要你装依赖。它不做 OCR，扫描件里的文字读不出来；远程（SSH）项目里的 PDF 要用远端机器自己的环境处理。

## 会话间协作与跨设备通讯

对话之间不是彼此隔绝的。一个对话可以去看另一个对话、给它派活、等它跑完，也可以跨电脑这么干。这套能力默认开着。

### 在输入框里点名一个对话

打 `@` 或点击输入框的加号，打开同一个引用与添加菜单。没有搜索文字时，菜单按来源列出插件、MCP、子智能体、标签页、设备、好友、命令和技能。文件与对话只在输入搜索文字后出现，各来源的候选合并排序，最多显示八项；对话搜索也能找到较早的会话。文件与文件夹使用引擎的文件索引并遵循 gitignore。

用 ↑↓ 选择、Enter 确认、Esc 关闭；Tab 保留普通焦点移动，不会选中候选。点击加号不会往草稿里插入字符。列表中的文件会成为引用块；「添加照片和文件」打开附件选择器。

选中一个对话，输入框里就多一颗**对话 chip**，显示它的标题。这颗 chip 不只是个标签——发出去的时候 Klaus 会知道「你在说哪一条对话」，并且拿到该怎么操作它的提示（读它、还是给它发消息）。所以「去看看那条叫某某的对话做到哪了」这种话，你不用去复制会话 ID。

点名一台**设备**同理：选一台同账号的电脑就得到一颗设备 chip，用来指明「这条消息要发到那台机器上的会话」。设备名字可以在桌面端改，见[设备与访问管理](/docs/ios/devices)。

点名一个**好友**则是把这条消息原文发给另一个 Klaus 账号，可以请对方处理或仅告知；请对方处理时，对方的 Klaus 按对方的设置在对方电脑上处理，这是另一套机制，见[好友协作](/docs/desktop/friends)。

### 它能做什么

- **看**：列出本机（以及同账号其他电脑）的对话、已归档的对话，读某一条的最近几轮。读不会把那条对话打开或唤醒。
- **等**：盯着一条或几条对话，等它们跑完或需要你介入——比自己反复去刷省得多。
- **说**：给另一条对话发消息。发过去的内容会作为一条用户消息出现在对方那里，对方看得见是你发的。
- **建与派**：开一条新对话、从当前对话分叉一条、把一条对话的标题/置顶/归档状态改掉。开新对话会立刻开始跑第一轮。
- **跨设备**：同一个 Klaus 账号登录的多台电脑之间可以互相发现、互相读、互相发消息。列出来的每台机器带在线/重连中/离线状态。远端只接受读和发消息；开新对话、分叉、改元信息仍然只在本机做。

### 对方收到的时候长什么样

一条从别的对话发来的消息，在接收方那里渲染成一个普通用户气泡，上面标一行来源：「由 Klaus 从『某某对话』发送」，跨设备来的则是「由某台设备上的会话发送」。所以它不会伪装成你亲手打的字。

如果消息到达时那条对话正在跑，它会被折进当前这一轮（模型立刻看到）；空闲时到达就开新的一轮。两种情况都算正常送达。

### 边界

- 改另一条对话（发消息、建对话、改状态）都是**逐次要批**的动作，不是「同意一次以后随便来」。这条比一个总开关靠得住：开关可以被一句话劝着打开然后忘了，逐次问则是每次都要你点头。
- 想让对话之间彻底不互通，把引擎配置里的 `thread_tools.enabled` 关掉，整套工具和相关的系统提示段落都会从下一条对话开始消失。
- 从别的对话来的内容算**不可信数据**：它可以被转述和分析，但那段文字里写的「指令」不会被当成你的指令执行。

## 好友协作

好友协作让两个 Klaus 账号互相发消息。你在对话里 @ 一位好友，写下要请对方做的事，消息原文直接发给对方；如果你请对方处理，**对方的 Klaus 在对方自己的电脑上**处理，用的是对方的模型、对方的文件、对方给的权限。结果用一条回复回到你发出请求的那个对话。整个过程是异步的：发出后你的输入框马上空出来，手上的事照常继续。

这个功能需要双方都登录 Klaus 账号。没登录时好友入口不可用，其余功能不受影响，见[账号与登录](/docs/desktop/account)。

### 加好友

侧栏固定入口里的「好友」打开好友页。右上角「+」菜单有三种方式：

- **添加好友**：输入对方的注册邮箱点「查找」，核对昵称和头像后「发送好友申请」。申请框里还可以先设好这位好友的「好友权限」，对方接受后立即生效。
- **我的二维码**：给对方扫。可以「保存我的二维码」「分享我的二维码名片」，也可以「复制链接」得到一条「添加我为好友链接」。对方在 Klaus 里打开链接时，会弹出预填好你邮箱的申请框，**仍要他自己点发送**，不会被一条链接直接加上。
- **扫码添加**：「使用摄像头」扫对方的码，或「选择二维码图片」识别一张截图。

对方会在「好友申请」里看到申请，可以「接受」或「拒绝」，接受时顺便选好接收任务的方式；你在对方处理前可以「取消申请」。双方确认后关系才成立。

「我的好友」里每一行显示对方是否在线、对方是否接收你的任务，以及你这边对这位好友的接收方式。行上有「发任务」（把这位好友直接放进输入框）和「好友设置」。

### 发消息给好友

在输入框里打 `@`，提及菜单的「好友」分组列出已加的好友（显示在线状态和对方是否接收任务），选中后输入框里出现带「好友」标记的好友提及。这时发送按钮前会出现一个下拉框：

- **请对方处理**（默认）：请对方的 Klaus 处理这件事。
- **仅告知**：只把消息送到对方那里，**不会启动对方的 Klaus**。对方会收到通知，消息留在对话里，需要时对方可以自己「交给我的 Klaus」。

只有输入框里那颗完整的好友提及会让消息发给好友；正文里手打一个名字不算。消息原文直接发出，**你的 Klaus 不会因此运行**。发出的**只有这条消息的文字**：附件会被拦下并提示移除，对话历史和文件都不会随之发出去。一条消息最多同时 @ 八位好友。

你也可以让自己的 Klaus 代你给好友发消息，比如说「把结论告诉小林」。这时它会请你先确认要发出的内容；是否每次都问，跟随这个对话的权限档。代发时对话里的内容可能被带给好友，但不会带上凭据。

#### 送达状态

发出的消息下方有一行状态，随进展变化：「已发送 · 尚未送达」→「已送达」→「等待对方授权」→「对方处理中」→「已回复」。其他情况会显示「等待补充信息」「被拒绝」「已取消」「执行失败」或「发送失败」。

- 对方还没处理完时，可以点「取消请求」，对方那边会停止这次请求；已经完成的操作不会撤销。
- 发送失败的消息可以「重试发送」，消息身份不变。

**对方离线也能发**。消息先保存在服务器上，对方的电脑一上线就会收到；请求不会因为时间过去而过期。

### 收到请求时

好友发来的消息出现在侧栏项目区里这位好友的分组下。同一个来源对话发来的消息会落进同一个配对的对话里，对话行上有「待回复」标记，好友分组上显示需要处理的数量；同时有系统通知。不想被打扰时，可以在好友分组的菜单里「静音此好友消息」。

请求怎么处理，取决于你在「接收任务」里给这位好友选的方式：

- **每个新会话询问一次**（默认）：好友请求在你这里新建会话时，出现一张首次执行审批卡，写明执行位置。点「允许此会话」后，同一会话里的后续请求直接处理；任务结束、取消或重启应用都不会撤销这次批准。也可以「拒绝」，或先「查看授权范围」。批准前多条请求共用一张卡，批准后依次处理。
- **按下方默认值自动执行**：不再询问是否接收任务，按设置的初始目录和权限开始。执行中是否需要批准，取决于会话当前的权限档。
- **不接收**：新请求自动谢绝，对方会看到被拒绝。

如果请求落在**你已有的对话里**（比如它是对你之前发出请求的回应），直接按那个对话自己的权限处理；对话忙碌时等待它空闲，不再显示好友新会话的执行审批卡。

**你本人发送的消息始终按会话当前权限执行，不受好友准入限制。** 即使好友请求还在等待首次批准，你也可以在那个会话里提问。你自己发言不会自动批准尚待处理的好友请求。

#### 处理与回复

对方 Klaus 的工作过程留在对方自己的对话里。结果要发给你时，它会用一次回复工具把结果交回去，对话里显示为「任务结果 · 这个请求标记为完成」。**它的最终回答只给它的主人看**，不会自动发给你。如果它需要你补充信息，会用一条提问发回来，你补充后在同一个对话里继续。

Klaus 处理完却没给出回复时，会先被提醒一次；仍然没有，对方（发出请求的人）会看到「{好友} 的 Klaus 已结束处理，没有附上结果」，主人这边会看到「Klaus 没有给出回复，已告知 {好友} 处理已结束」，并可以点「让 Klaus 回复 {好友}」补上。

回复回到你发出请求的那个对话，标着「{好友} 好友 的回复 · 回应你 HH:MM 的请求」，点后半句可以跳回原来的请求。鼠标移上去有「回复对方」和「交给我的 Klaus」两个按钮。超过 12 行或 800 字的长消息先折叠成摘要，可以「展开全文」「在阅读器中打开」或「复制全文」。原来的对话已经删除时，回复会放进一个新对话里。

回复送不出去时（最常见的是你离线），对方电脑会按 15 秒、1 分钟、5 分钟、15 分钟、1 小时的间隔自动重投，看到你上线会立即再发；被服务端明确拒绝的就停止重投。

#### 运行中

- **没有时长上限**：好友任务一直跑到它自然结束。
- **目录与执行权限**：范围外的操作与普通会话一样进入当前权限档的批准或审核流程；完全访问解除普通目录沙箱。仍可通过「目录权限申请」把目录加入默认可写范围，并选择记入该好友的常驻设置。
- **停止**：在对话里直接停止；或者把这位好友改成「不接收」、删除好友，都会取消这位好友待处理和正在运行的任务（改成不接收前会提示要取消几个）。

### 设置 → 好友

账号分组下的「好友」页管两件事：

- **接收电脑**：好友的任务投到哪台电脑。不选时是「全部在线电脑（默认）」；选了某一台，就只投到那台。
- **默认好友权限**：适用于你添加的好友和你接受的好友申请，之后可以给每位好友单独调整。包括：
  - **接收任务**：每个新会话询问一次（默认）、按下方默认值自动执行、不接收。
  - **执行权限**：新好友会话的初始权限，可选「请求批准」（默认）、「帮我批准」、「完全访问权限」，含义与普通会话相同。会话建立后可以单独改档，重建时保留该会话自己的选择。
  - **执行位置**：「普通会话」（默认）、某个项目或某个工作区。选项目或工作区时，任务会话归入它的分组，可以读写它的目录。
  - **允许任务命令访问网络**：默认开启，可以关掉；应用自身的联网能力由所选应用决定。
  - **允许 Computer Use 操作应用**：默认关闭，打开后只能操作你勾选的应用。
  - **文件与目录**：「添加目录」保存额外路径；「可编辑」的目录加入初始默认可写范围，「只读」目录不预先放行写入。实际读写仍按会话当前的三档权限判断，新加的默认只读。
  - **好友共享空间**：每位好友自动有一个自己的子目录（`~/.klaus/friends/<好友关系 id>/`），好友任务从这里开始，始终可编辑。默认可写目录只包含该好友自己的子目录；选择项目或工作区时再叠加对应目录。

目录配置提供会话初始化的默认范围，不再额外限制完全访问。请求批准和帮我批准对范围外操作走普通会话的批准流程；Computer Use 所选应用授权独立生效，见[权限是怎么判的](/docs/desktop/permission-resolution)。这些设置只存在本电脑。

好友页某位好友的「好友设置」里，可以写**备注**（只保存在本电脑，好友看不到，参与显示和搜索）、单独调整这位好友的**好友权限**，或者「删除好友」。删除后双方不再是好友，任务授权同时撤销，双方本地的聊天记录保留。

全局搜索（⌘/Ctrl+K）也能搜到好友对话。

## 迷你窗口与桌宠

迷你窗口是一个浮在所有应用之上的小助手。不打开主窗口，也能在它上面看到哪些会话在跑、哪些在等你，直接处理审批和提问、发一句新任务，或者开口跟 Klaus 语音对话。它可以只显示一排紧凑的按钮，也可以由一只桌宠「站」在上面。

设置在「设置 → 迷你助手与桌宠」。迷你窗口默认关着，点页面右上角的「显示迷你窗口」，或按它的全局快捷键，就会打开。

### 召唤与可见性

- **快捷键**：默认 macOS 是 ⌥Space，Windows 是 Win+Alt+P，在任何应用里都能用，按一次显示、再按一次隐藏。设置页顶部可以改：点那个按键框，按下新组合即保存；旁边的叉号清除。它和「设置 → 键盘快捷键」里的「显示或隐藏迷你助手」是同一项，改哪一边都一样。
- **可见性**：「始终可见」让迷你窗口常驻桌面；「按需显示」只在按快捷键时出现，点到窗口外面就自动隐藏。
- 迷你窗口可以拖到屏幕任何位置，靠到屏幕左右边缘能收起成一条，点一下再展开。右键打开菜单：打开 Klaus、显示活动、显示桌宠、选择桌宠、设置、隐藏迷你窗口。

### 能在上面做什么

- **看活动**：需要你关注的会话按状态列出：正在运行、需要输入、已就绪、受阻，带项目名和改动文件数。点一条「打开任务」跳回主窗口那个会话；不想再被打扰的会话可以在右键菜单里「静音通知」，已完成的可以一键「清除已完成」。整块活动也可以在右键菜单里隐藏。
- **直接回复**：等你审批的权限卡可以就地「允许一次」或「拒绝」；Klaus 向你提的问题可以就地作答，可选的问题也能跳过。计划确认这类需要细看的，可以「查看」后再决定。
- **发消息**：在「向 Klaus 提问…」里写一句话就开一条新会话发出去；对着某条活动点「回复」，就是给那条会话追加消息。可以附文件、图片，也可以「截取屏幕」选一个窗口或整个屏幕作为附件。单条上限 8000 字。输入框还带听写麦克风，复用你在[语音输入](/docs/desktop/voice)里配置的来源，识别结果先写进草稿，改好再发送。
- **语音聊天**：点麦克风按钮开始。你说完一句，它自动识别、作答并把回复念出来；你开口说话或点「打断」可以随时截住正在播的回复。麦克风和扬声器可以分别静音。语音对话会在 Klaus 里生成一条普通会话，可以「打开会话」接着用文字聊。实时语音自动跟随主窗口当前选中的会话，不需要在迷你窗口里单独切换。

语音聊天使用「设置 → 语音」里选好的实时语音来源。来源不可用或未配置时，按钮会直接写明原因，并提示先去配置。

### 桌宠

「我的桌宠」里排着可选的形象。第一格「无」是不带形象的轻量模式，只留迷你窗口本身；其余是九款内置桌宠：Klaus、Luma、Wick、Quill、Dapple、Morrow、Wisp、Amble、Twill。它们有待机、跑动、挥手、跳跃、等待、运行、出错等动作，会随任务状态变化，眼睛也会跟着鼠标转。

- **大小**：「自定义桌宠」里调桌宠大小，80 到 224，默认 112，「重置」回默认。
- **从文件导入**：选一张透明背景的 PNG 或 WebP 精灵图。格式是 8 列，9 行（1536 × 1872）或 11 行（1536 × 2288）；11 行的版本多出两行，用来画十六个方向的视线。
- **从网址导入**：填精灵图网址，先「预览」确认动起来是对的，再填名称和描述「添加桌宠」。
- **创建桌宠**：Klaus 会在主窗口开一条新会话，用内置的桌宠制作技能先问你想要什么角色，再生成并校验精灵图，做好后自动加入列表。
- 自己导入或创建的桌宠可以「删除桌宠」，内置的不能删；旧格式（9 行）的自建桌宠会多一个「更新」，让 Klaus 补上视线方向。导入的文件放在 `~/.klaus/pets/` 下，「打开文件夹」直接定位到那里。

## 回答风格

输出风格（Output Style）决定 Klaus 回答的人格与结构。切换风格只换表达方式，不改它的能力和权限。

- 风格清单 = 内置的两个人格 + 你自己写的。内置只有 **Explanatory**（边做边解释它为什么这么实现、以及仓库里的惯例）和 **Learning**（会停下来让你自己写一小段代码练手），另外那个「默认」不是风格，而是「不套任何风格」。
- 自己写一个：放一份 `.md`，文件名就是风格 id。读取顺序是先看全局 `~/.klaus/output-styles`，再从会话的工作目录往上逐级找各级 `.klaus/output-styles`（到仓库边界为止），同名的后者盖掉前者——所以项目里能放一个只在这个项目生效的风格。前置属性里 `name` 不写就用文件名，`description` 不写就取正文第一行。
- 选中的那一个作为引擎配置项存下来，会话启动时随初始化下发（引擎自己不带任何内置风格，只按名字从下发的清单里挑）。已经开着的会话在下一回合之间自动重建并带上新风格，不必特意重开。
- 它只改系统提示里「怎么表达」那一部分，不动工具清单、不动权限，所以换风格不会让它变得更能干或更受限。前置属性里只有 `name`、`description` 和正文会真正被用上；网上流传的 `keep-coding-instructions` 这类字段虽然能写在文件里，引擎并不读它，写了也不会改变任何行为——想要纯聊天人格，直接把正文写成那样就行。

## 语音输入

点击对话输入框旁的麦克风开始听写，再次点击结束。「设置 → 语音」管理听写来源、语音识别整理、个性化表达、词典和实时语音来源。识别语言跟随系统，不提供识别方式或额外的识别语言开关。

- 听写使用你选定的识别来源。支持实时识别的来源会在说话时显示临时文字，结束后保留完整内容；来源不可用时会提示恢复连接，不会自动改用另一个账号。
- 支持原生整理的实时来源会在开始录音时接收词典、表达偏好和对话上下文，并通过同一语音会话返回完整整理结果。正常完成时直接采用结果；响应较慢时，文字模型会并行整理完整识别文本，采用先完成的整理结果。文字整理和修正学习使用「默认模型 → 辅助任务模型」里的语音识别整理选择，支持所选订阅来源和自定义模型；未指定时跟随所属聊天的主模型，独立听写使用记住的新聊天默认模型。每次请求读取当前设置，已经开始的请求保留原模型。短暂等待不会使原文替代尚未完成的整理。来源不支持原生整理时，使用该文字模型；模型不可用或请求失败时，保留识别原文。
- **个性化表达**从修正中学习一般性的表达风格。停用时通过更多菜单确认，重新启用可直接点击按钮。停用后使用通用措辞，词典及词语修正学习仍可使用。没有单独的语音记忆列表。
- 听写上屏后，会在当前输入框中短暂跟踪修正。继续编辑会重置约 15 秒的等待时间；离开输入框或发送时也会检查。未修改、清空或大幅重写的草稿不会作为语音修正学习。学习需要有可用的文字模型。
- **词典**支持新增和编辑词条、搜索，以及按全部、自动添加、手动添加筛选。每条最多 100 个 UTF-16 单元，不会因新增词条而淘汰已有词条。行内复选框用于选择批量删除，不是启用开关；单条和批量删除均需确认。
- 自动学习加入的词条会显示撤销通知。撤销只移除这次新加入的词条。
- CSV 导入使用无表头的单列文件，每行一个词条。文件最多 5 MiB，每次最多 3000 个不同词条；导入前会预览待加入的词条。超过长度限制的词条会跳过，同一行有多个非空单元格则拒绝文件。
- 每次录音最长 5 分钟。转写历史保存在本机，默认保留 30 天，可用于区分识别错误与整理后的变化。

## 远程主机（SSH）

会话的工作目录可以放在远程主机上。Klaus 读你本机的 SSH 配置列出可用主机，可以测连通、浏览远程目录、把某个远程路径设为工作目录。登录需要交互输入密码或口令时仍由你在界面上回答，Klaus 不代你填。

- Klaus 自己说 SSH 协议，不调系统的 `ssh` 命令。远程工作目录是一个 `ssh://[用户@]主机[:端口]/绝对路径` 字符串。
- 主机信息读你自己的 `~/.ssh/config`（HostName / User / Port / IdentityFile，`Include` 展开一层，先出现的值生效）。
- 主机指纹按 accept-new 处理：没见过的主机记下来，指纹变了的直接拒连。
- 认证顺序：ssh-agent → 私钥文件（加密私钥会问你口令）→ keyboard-interactive → 密码。需要输入时是界面弹框问你，可以等你几分钟；你输的密码只用于这次认证。
- 每个目标保持一条已认证连接复用，每条命令在它上面开一个通道，不会每次重新认证。连接 10 秒超时。
- 暂不支持 ProxyJump / ProxyCommand——碰到会明确报出来，而不是装作连上了。
- 远程根目录不会被算进本机沙箱的可写根：那是远端的路径，本机的路径闸门管不着它。

### 概览面板各区

- **计划**：执行时的任务清单与进度，没有任务时是空的。完整提案在对话里审阅，右侧计划标签页用于编辑全文。
- **子智能体**：派出去的后台子智能体，每行一个头像、任务名和状态。只列后台的那些。
- **后台进程**：Klaus 起的长命进程（比如一个开发服务器），以及它们还在不在跑。
- **电脑操控**：只在电脑操控真的动过手时出现。
- **产物**：这条会话改过或生成的文件，点开就地预览，可切源码与预览，也能单开一个窗口或在访达里定位，见[会话产物](/docs/desktop/session-artifacts)。浏览整个项目目录用的是「文件」面板。
- **引用**：这条会话实际用到的东西，分技能 / 记忆 / MCP 三个子档——「它为什么知道这个」通常在这里能查到出处。

上下文用量不在概览面板里，它是输入区旁边那个圆饼 chip。

### 手机端是怎么接上的

回答「为什么手机连不上」就看这里：

- 桌面端开的那个本地服务只绑 `127.0.0.1`，**不开局域网**。手机能连上是因为桌面端主动向外拨一条 WebSocket 到中继，中继再把手机的请求从这条连接回灌到本机。所以不需要同一个 Wi-Fi，也不需要开端口。
- 中继只是管道，不多给权限：隔着中继过来的请求最终走的是桌面界面自己用的那套接口，所以手机上能做的不会多于桌面上能做的。
- **必须先登录 Klaus 账号**：中继要拿账号验这台桌面端。没登录时这条腿根本不启，页面上直接写「请先登录」，而不是永远转圈「连接中」。
- 配对凭据是有的，但**刻意没有摆到界面上**：设置页只有「允许远程控制这台设备」一个开关，加一份账号设备列表（可以改名、可以移除），没有配对码、没有二维码、也没有重置按钮。要断开一台设备就在列表里移除它，或者直接关掉那个开关。
- 断线会自己重连（1、2、5、15 秒递增），平时每 20 秒一次心跳。设备在列表里显示在线 / 重连中 / 离线三态。

## 让 Klaus 操作 Klaus

客户端的功能不止能点，也能说。直接在对话里说「把定时任务列出来」「把这个技能停掉」「打开权限设置」「建一个每天早上九点的任务」，Klaus 会去调用客户端自己的控制接口执行，而不是只告诉你该点哪里。

- 读取类操作（列清单、查状态、看配置）直接执行。
- 改动类操作（启停、创建、切换）执行前会说明它要做什么。删除、清空、断开连接这类不可逆动作需要你明确同意才会真正执行；被拒一次它不会自己补上同意，也不会绕去找一个不需要同意的等效动作。
- 界面跳转：让它「打开某个页面」会直接把窗口切过去，你看到的就是刚讨论的那一页。
- 不是每块面板都整条交给它。需要扫码配对、要弹系统文件选择框、要你亲手填密钥的那部分故意只留在界面上；碰到这种它不会瞎试别的动作，而是把对应的页面打开，剩下的你自己收尾。
- 凭据不经过它：它读到的 API key、配对令牌一律是「已隐去」，所以它只会把你送到对应设置页，不会把密钥念给你听。
- 从别人那里来的文字——频道里别人发的消息、第三方技能/插件/MCP 服务器自带的描述、以前的会话或记忆里存下的内容——会被标成不可信数据。它可以转述和分析，但那些文字里写的「指令」不会被当成你的指令执行。
- 需要控制接口单独确认的不可逆动作，仍要求主人明确同意；后台定时运行不能代替主人提供这份同意。它只会把「本该改什么」写进运行结果，等你在主窗口决定。
- 它也能查阅本手册，所以关于 Klaus 自身的问题（某个开关什么意思、为什么某个功能没生效、某个机制怎么工作）可以直接问它。

## 从其他客户端导入

如果你之前用其他智能体客户端，Klaus 能探测本机已装的那几家，把可核实格式的内容导过来（「设置 → 导入」）。导入是复制，不会改动原客户端的数据。

- 探测三家：**Claude Code、Qoder、Codex**。探测靠它们在本机的固定目录，没装的就不会出现。页面上只列「已核实格式」的来源——格式没核实过的客户端不会出现在列表里，而不是导到一半失败。
- 能导四类：**历史会话、技能、MCP 服务器、项目根目录**。可以整体导，也可以逐项挑。
- 明确**不导**的：设置、钩子、命令、子代理、指令文件（AGENTS.md 之类）、已启用的插件。这几类目前没有可信的跨客户端转换——不同客户端的钩子和命令语义并不等价，硬转过来等于给你埋一个会静默跑错的东西，所以宁可报错也不猜。Qoder 的原生聊天格式也还不支持。
- 落点：技能被复制进 `~/.klaus/skills`（或项目的 `.klaus/skills`），目标已存在同名目录时跳过并告诉你；会话记录转成 Klaus 自己的格式写进会话存储根 `~/.klaus/sessions/`，并标记为外部来源；项目根只是登记一下，不搬目录。
- MCP 配置按**白名单**归一化：只保留启动真正需要的字段（命令型的 command/args/env，HTTP 型的 url/headers/oauth），其余字段一律丢弃。**但 env 和 headers 里的东西是原样带过来的**——如果原来那份配置把密钥写在环境变量或请求头里，它会跟着进 Klaus。导入完去 MCP 页核对一遍这些值，见 [MCP 与连接器](/docs/desktop/mcp)。Codex 的项目级 MCP 还多一道要求：那个项目必须是已登记且被 Codex 标为 trusted 的。同名服务器不会覆盖你已有的那条，直接跳过。
- 重复导入会被跳过：一份导入台账记着每个来源会话文件的路径和内容哈希，没改过的文件第二次导入直接跳；源文件改过（哈希变了）可以再导一次。
- 会话导入有量的上限：一次最多 50 条，默认只看最近 30 天。
- 导完如果 MCP 配置变了，会顺手让运行中的会话重新加载 MCP，不用重启应用。但技能是在会话启动时读盘的，Klaus 也不监听那个目录——导入是直接往磁盘上写文件，走不了「在 App 里改→下回合自动重建」那条路，所以要开一个新会话才看得到（见[扩展怎么被加载](/docs/desktop/extension-loading)）。

## 顾问

在「设置 → 模型分工与编排」的顾问区域先选来源、再选模型，并开启顾问。模型行只列当前来源的模型；开启了但没选模型，等同于没有开启。所有聊天共用这个选择；顾问可以来自与主模型不同的来源，不要求比主模型更强，也不占用高中低模型档位。

### 什么时候请教

启用后，主模型会获得 `advisor` 工具，以及在开始实质工作前、遇到困难、考虑换思路和完成前请教的指导。具体由主模型决定何时调用，并不是每次回复都额外请求一次。

主模型把问题交给工具，工具将当前有效的对话上下文发送给所选顾问模型。上下文包括对话、已有工具调用及结果；已经压缩的历史以当前摘要为准，不会重新读取所有历史日志。顾问只返回建议，不执行工具、不修改文件，也不会再次调用顾问。主模型收到建议后继续处理任务。

### 模型与设置

- 顾问模型单独保存，切换聊天或主模型不会更换顾问。
- 更换顾问模型会立即保存，设置在下一回合生效，不改变正在运行的回合。
- 关闭顾问会保留已选模型，方便以后重新开启。
- 所选来源未登录、模型不可用或请求失败时，会显示错误，不会偷偷换成其他模型。
- 顾问无法读取上下文中的图片、文档时会明确报错。上下文超过顾问容量时，会先由当前聊天本次使用的主模型生成摘要，再交给原选定顾问；主对话历史保持完整。
- 摘要会保留问题相关的目标、约束、决定、证据来源和未决事项。压缩失败、被取消或摘要仍放不下时，会明确报错，不会静默截断或切换模型。

### 上下文、额度与缓存

顾问咨询会把当前上下文或其摘要发送到你选择的来源，并使用该来源的额度或产生相应费用。需要摘要时，还会额外使用当前主模型的额度；摘要请求与顾问请求分别计费，并受会话费用上限约束。选择另一个来源前，请确认该来源适合接收这段对话及其中的工作内容。

顾问使用独立的请求与缓存标识，固定指令保持稳定，本次问题追加在上下文后面。主模型与顾问的缓存不能假定共用；是否命中以及计费方式取决于对应模型来源。摘要使用独立的缓存标识，不写回主对话。停止当前回合会取消正在进行的摘要或顾问请求；两个阶段共用一次咨询的总超时。

## 反馈与建议

这两件事入口不一样，值得说清楚：

- **报问题**在每条会话的 ⋯ 菜单里（「报告问题」），跟着当前会话一起提交。
- **提想法（建议）在窗口里没有入口**——不是藏得深，是确实没有。要提就直接跟 Klaus 说，它替你提交（可以附文件）。

- 反馈会自动收集，不用你自己贴：会话 id、这条会话的工作目录、完整对话记录文件的路径（存在才带）、该目录的 git 分支/HEAD/有没有未提交改动，以及系统、机型和应用版本。反馈必须挂在一条会话上，没有会话就提交不了。
- 建议可以附最多 8 个文件、合计不超过 20 MB；同一个文件重复选只算一次。描述超过 8 万字会被截断，并在末尾注明截掉了多少。
- **先落本机，再上传**：不管发不发得出去，报告都会先写成一份 JSON——反馈在 `~/.klaus/feedback/fb_*.json`，建议在 `~/.klaus/suggestions/sg_*.json`。所以提交失败内容也没丢，可以自己打开那份文件看或转发。
- **没登录就只存本机、不发送**：上传要带桌面端的登录令牌，未登录时界面会提示「请先登录 Klaus 账号，再提交给支持团队」，提交结果里也记着是因为未登录跳过的，不会假装成功。想真的送到 Klaus 团队就先在账号页登录。
- 这是发给外部的动作，所以让 Klaus 代你提交时，它会先把要发的内容给你看并等你同意。

## 技能

技能是教 Klaus 完成特定任务的说明书，命中场景时自动加载。

- 市场档：卡片网格浏览技能市场，一键安装。
- 已安装档：列表管理已装技能，可启用/禁用；顶部作用域切换在「全局」和各项目之间切换——全局技能所有会话可用，项目技能只在该项目生效。
- 技能也可由你自己编写，或让 Klaus 帮你创建。

磁盘上的形状与几个容易踩的点：

- 一个技能就是一个目录，里面必须有 `SKILL.md`；开头一段 YAML 前置属性声明它的名字、描述、图标、标签、允许用的工具，以及适用系统和依赖（需要哪些命令、哪些环境变量）。描述写得准不准直接决定它会不会在对的时候被用上。
- 位置：全局 `~/.klaus/skills/<技能名>`，项目 `<项目>/.klaus/skills/<技能名>`（只限已登记的项目根）。项目目录下只有带 `SKILL.md` 的目录才算技能，不会把仓库里碰巧同名的目录当成技能。
- 安装：从云端市场下压缩包（包 ≤ 256MB、解开后 ≤ 512MB）。市场内容现在完全由服务端托管，客户端不再随包内置一份本地副本——所以离线时技能广场会直接显示一条错误，而不是退回一份内置清单（未登录的游客也能看和装，市场接口是公开可读可装的）。装过什么、装的哪个版本记在 `~/.klaus/skills/.install-records.json`，「有更新」就是拿它比出来的。更新按技能名进行，不指定版本就取最新。
- 禁用不删文件：只在 `settings.db` 里记一行「这个技能关着」。所以禁用可逆，重新启用不需要重装；真要删掉才是卸载。
- 生效时机：安装、修改、启停或删除技能后，已经开着的会话和输入框里的 `/` 菜单、技能菜单会自动更新到最新内容，不用重开会话，也不用重启应用。直接在磁盘上改 `SKILL.md` 也会被发现，最多稍等十秒。已经发出的请求继续用它开始时的那份技能清单；每个会话自己的技能范围（全局、哪个项目）保持不变。

### 内置的 PDF 技能

Klaus 自带一个 PDF 技能：提取文字和表格、把页面渲染成图片检查版式与图表、生成新的 PDF，以及拆分、合并、旋转。它需要的 Python 运行环境由 Klaus 自己管理：第一次用到时自动下载并校验，之后重复使用，不碰你机器上自己的 Python。它不带 OCR，扫描件里的文字读不出来；远程（SSH）项目里的 PDF 要用远端机器自己的环境处理。

## 插件

插件是打包分发的能力集合，一个插件里可以同时带技能、斜杠命令、子代理、MCP 服务器和钩子。

- 市场档：从插件市场浏览并安装。每行「装了会多出什么」是引擎用真正加载时那套解析器算出来的，所以不会出现「市场页写的和装完实际有的不一样」。
- 更新检查：打开插件页、重新聚焦窗口和后台检查都会获取新目录；五分钟内复用检查结果，后台每三十分钟检查一次。检查不会自动安装新版，离线时保留上次目录。刷新按钮可以立即重新检查。
- 更新：市场卡片和已安装列表显示已装版本、可用版本和「更新到」按钮。「可更新」集中列出新版，「全部更新」按队列逐个处理。每个插件独立显示进度和结果，更新一个插件时仍可浏览和操作其他插件；失败保留当前安装，可查看原因后重试。更新保留启用状态和插件数据，过期更新会被引擎拒绝。
- 已安装档：启用/禁用开关。注意插件启停是应用级的，没有项目作用域——启用后所有会话可见。
- 已装列表里的「已加载 / 加载失败」是某一条会话的运行时状态，不是全局属性：同一个插件可以在新会话里好的、在旧会话里还是旧状态。

它的安装与生效机制：

- 账本归引擎所有，存在引擎自己的配置文件 `~/.klaus/config.toml` 的 `[plugins]` 段里，每条记录带名字、来源、安装路径、安装时间和启用位。这份文件由引擎读写，不要拿第二个写入方去改它的形状——引擎启动时要解它，形状不对会启动不了。已登记的市场目录同样记在这份配置的 `[marketplaces]` 段。
- 安装分两段：客户端先把包取到一个暂存目录（本地复制，或 git 拉取——支持仓库地址、`owner/repo` 简写、以及只拉仓库里某一个子目录），再交给引擎校验、复制进它自己的存储区、写账本。无论成败暂存目录都会被清掉，所以安装失败不会留下半个插件。
- 启停改的是账本里的启用位。安装、更新、启用和停用成功后，页面按引擎回执说明何时生效：空闲会话可接收已发布的插件变更，运行中的回合在下一回合使用新版。只有引擎明确要求重新连接或重启时，页面才提示重启。插件已保存而后续界面刷新失败时，会保留成功结果并单独提示刷新问题。
- 卸载同时删账本行和存储区里的那份副本。内置的那几个（比如浏览器）标为内置来源，可以停用但卸不掉。
- 插件里的技能/命令/子代理/MCP/钩子由引擎自己从账本加载并标上来源，客户端不再重复报一遍（否则插件里的钩子会每个事件触发两次）。

## MCP 与连接器

MCP 页管理 Klaus 可调用的外部与系统能力。

- 内置能力：电脑操控（让 Klaus 像人一样点击、输入操作桌面应用）以原生能力卡片形式出现，点卡片进入开关与配置。（浏览器操控曾也是这里的一张原生能力卡，它现已归为内置插件，开关与配置面搬到了插件页。）
- 系统连接器：接入 macOS 本机数据与应用，如信息（Messages）、Safari 书签与历史、照片、App UI 等。部分连接器需要先完成系统授权（见下文「系统授权」），授权前保持关闭。
- 市场与自定义：可从市场安装 MCP 服务器，也可手动添加自定义 MCP 服务器。连接器目录现在完全由服务端托管，客户端不再随包编译一份种子——好处是服务端上新后所有客户端不用发版就能看到，代价是服务端不可达时连接器市场会是空的（和技能广场同一个取舍）。

MCP 服务器有三个作用域：全局（所有会话可用）、项目（写在 `<项目>/.klaus/mcp.json`，随仓库提交、团队共享）、本地（写在引擎配置 `~/.klaus/config.toml` 里这个项目路径名下，仅本机私有、不进仓库）。「已安装」档顶部是一排平铺的标签：「全局」加上每个已登记项目各一个；在项目标签里，每行用「项目」或「本地」标出它属于哪种。项目作用域的配置在会话启动时读取，改完要开新会话才生效。另外，由插件带来的 MCP 服务器会在行上打一个「插件」来源标记——它是一个来源标签，不是你能选的作用域。「服务器装了但工具不出现」的原因按常见程度排：需要授权的服务器（OAuth）在完成授权前一直不可用，MCP 页会把这类服务器单独标出来、可以就地补授权；其次是启动命令依赖的运行时不在（`npx`/`uv` 这类，MCP 页有检测入口）；再次是服务器本身或那个工具被单独关了——单个工具可以单独关掉，不必禁掉整个服务器。

（历史上还有一道「项目信任」闸门，现在已经取消了：不会再因为没确认信任而拿不到工具。）

## 浏览器操控

让 Klaus 自己开网页、点链接、填表单、截图读页面。两种跑法：

- 内置浏览器：Klaus 自带的浏览视图，开箱即用，但不带你平时的登录态。
- Chrome 桥：装上 Chrome 扩展后接管你自己的 Chrome，所以已登录的站点直接能用。

浏览器操控现在是**一个内置插件**，开关与配置面长在插件页的那张卡上（它曾经是 MCP 页的一张原生能力卡，见 [MCP 与连接器](/docs/desktop/mcp)）。默认走 Bing 浏览器搜索的联网能力也跑在这套浏览器上，所以要用内置搜索得让这个插件开着，见[偏好设置](/docs/desktop/preferences)的「联网」。

### Chrome 扩展怎么装

接管你自己的 Chrome 需要装一个扩展，并接上本地的消息代理（native host）。卡上给了两条路径，外加一份诊断：

- **一键准备安装**：把「部署扩展文件 + 复制它的本地路径 + 打开 Chrome 扩展管理页 + 在访达里定位到扩展目录」四件事合成一次点击。想看清每一步的人可以走下面的分步区，但一键那条不是必经之路。
- **系统策略零手势安装**（仅 macOS）：直接写 Chrome 的 `ExtensionInstallForcelist` 策略让扩展自动装上，用户一次手势都不用。这一条会探测机器是不是被 MDM 管着的——受管的机器上策略由 IT 下发，Klaus 会告诉你为什么这条路走不通并退回手动安装，而不是悄悄失败。装与卸这一步都要你明确同意。
- **诊断**：报扩展连没连上、native host 装没装、当前连的是哪个 Chrome 实例（带版本），以及「按了没反应」时该看哪一项。

### 网页权限与标签页引用

内置浏览器里的网页请求定位、通知、摄像头这类权限时，不弹系统原生框，而是在 Klaus 里弹出「浏览器权限」对话框，写明是哪个网站（「{网站} 请求 {权限}」），由你选择允许或拒绝。

想让 Klaus 处理某个已经打开的页面时，在输入框里打 `@`，从「标签页」里选中它。这个引用精确指向那个浏览器和那个标签页，排队中的消息里也可以用，免得它去猜你指的是哪一页。

### 可配置项

这几项没有摆成设置页上的控件，但都能改——直接让 Klaus 改即可，它会调浏览器自己的控制面：

- 确认策略（哪些动作需要问你）、截图策略、允许访问的站点白名单（加 / 删域名）。
- 浏览数据可以清掉（Cookie、缓存、或全部），这一步不可逆，所以执行前要你明确同意。

## 电脑操控

让 Klaus 像人一样看屏幕、移鼠标、敲键盘，操作那些没有接口的桌面应用。需要先完成辅助功能与自动化授权（见[系统授权](/docs/desktop/system-permissions)）。

它的形态和普通开关不一样：

- 它对引擎是一台内置的 MCP 服务器，开关与配置面长在 MCP 页的原生能力卡里。开启后会给会话多出一组桌面操作工具：列出电脑上的应用、读一个应用当前窗口的状态（带截图和无障碍树）、点击、右键菜单动作、填值、选文本、滚动、拖拽、按键、打字，再加上读/改上面那份应用策略、以及三个录制控制工具。（浏览器操控也曾是一张原生能力卡，它现已归入内置插件，配置面在插件页。）
- 干活的是一个随应用分发的原生小助手进程，Klaus 用标准输入输出给它送指令。它直接调系统接口完成动作——用辅助功能接口读控件树、用图形事件接口注入鼠标键盘、用系统的屏幕捕获框架截屏，不需要额外装任何运行时。系统授权记在这个小助手进程身上，而它由正式安装的 Klaus 拉起。
- 开启连接器后，默认所有本地应用都可进入授权流程。首次使用应用时询问，选择“始终允许”后会记住选择；已有应用清单保留为始终允许记录，不再限制其他应用。明确禁止的应用仍会被拒绝，好友任务仍只允许其单独授权的应用。
- 在设置 → 电脑操控中查看“始终允许的应用”，点击“添加应用”可填写应用名称或完整应用路径，保存后使用该应用时不再询问。点击行尾删除并确认即可撤销记录，下次使用时重新询问。此页不重复提供连接器总开关。普通策略条目按归一后的包含关系匹配；`bundle:` 和 `name:` 条目分别精确匹配应用标识和名称，`app:self` 识别当前安装的 Klaus。
- 它不会在每次点击前重复询问。同一电脑操控会话记住本次同意；每一轮动手前仍先读取一次窗口状态，每次读取都会附带截图。
- 清单每次动作都从设置里实时读，不做缓存——所以你在对话里让它改清单，下一个动作就按新清单算，不用重连也不用重启。同理，让它「以后别碰邮件」这种话是直接改这份清单，说完立刻生效。
- **你在用电脑时它会让路**：每个写入类动作（点击、打字这些）之前先探一眼最近有没有人在动键鼠——1.5 秒内有输入、且比它自己上一次动作更晚，就算你在用。此时这次动作直接被拒，并让模型等 2 秒再试，而不是跟你抢鼠标。
- **锁屏时默认停手**：屏幕锁着就直接告诉模型「让用户自己解锁」。自动解锁是可选的，而且有意做得保守：登录口令只在系统弹出的对话框里输入、只存系统钥匙串，既不进对话也不进日志；检测到有人在现场（最近几秒有人动过键鼠）时一律不自动解锁。还要知道 macOS 在锁屏界面开着安全输入，普通签名应用注入按键会被系统拒绝，所以自动解锁大概率解不开，仍会退回让你自己解锁。
- 辅助功能、屏幕录制这类系统授权只能你自己在系统设置里给，任何程序都不能代写；而且 macOS 对已运行的进程缓存权限结论，给完要重启 Klaus。

演示录制（你做一遍给它看）：

- 入口在技能页的「录制技能」：它会开一条会话，由 Klaus 起录制。录的是**你自己**的操作——点了哪个控件、输了什么字、切到哪个窗口，记的是无障碍语义（应用名、控件角色与标题）而不是像素坐标，也不录屏幕视频。
- 录制期间屏幕上有一个悬浮小面板，只有停止和丢弃两个按钮。一次录制最长 30 分钟，忘了停会自动收尾（连接进程中途挂掉也不会丢，已经落盘的事件下次仍能收尾）。
- 停下来之后 Klaus 读这份事件流，把它写成一份技能（`~/.klaus/skills/<短名>/SKILL.md`，固定包含概述、前提、复现步骤、验证、待确认项）。所以下次「照着做」照的是这份说明书，不是回放录像——能换窗口位置、能挑更合适的工具替代硬点击。
- 隐私：密码框不记录（逐个按键探测安全输入）、像凭据的文本落盘前就打码、阻止清单里的应用不录——「永远别碰这个应用」同时意味着「也别录它」。

## 钩子（Hooks）

钩子是在固定生命周期点上执行的 shell 命令，比如工具调用前、一轮结束后。用它可以把格式化、测试、通知这类动作接进 Klaus 的循环。

- 可挂的事件共 17 个：会话开始/结束、你发出提示词、工具调用前/后、工具失败、一轮停下、子代理开始/结束、压缩前/后、通知、Setup、任务创建/完成、工作树创建/移除。事件名写错的条目会被直接丢掉，不报错，所以看起来就像钩子没写一样。
- 存放位置：全局 `~/.klaus/hooks.json`，项目 `<项目>/.klaus/hooks.json`。文件形状是「事件 → 若干组 → 每组一个可选 matcher 加一串钩子」，matcher 属于组而不是单条钩子。同一事件先跑全局再跑项目，同一文件内按书写顺序跑。
- 只有 `type: "command"` 的条目会真的执行；同组里其他类型被跳过，不影响旁边的命令条目；缺 `command` 的同样跳过。`timeout` 写的是秒，不写默认 30 秒；`async: true` 的钩子不阻塞这一轮。
- 执行方式：引擎起一个 `bash -c` 进程，把一份 JSON 从标准输入喂给它；如果标准输出是 JSON 就按结构解析。退出码非零或输出不是 JSON 时，这次钩子记为失败但不会拦住工具调用。
- 钩子不只是旁观者：工具调用前的钩子可以在输出里直接给出放行、拦下或「改成问你」，拦下时这次调用直接失败、连权限卡片都不会弹；提示词钩子可以挡掉你这一整条消息；停下钩子可以不让这一轮结束。多个钩子同时表态时，拦下最硬（第一个拦下的说了算），其次是改成问你，最后才是放行。
- 钩子清单在会话启动时随初始化一并交给引擎，引擎自己不读 `hooks.json`。在「设置 → 钩子」里信任、停用或改动钩子后，已经开着的会话会在下一回合自动重建并带上新清单；直接在编辑器里改 `hooks.json` 文件不会触发重建，要等下一次在应用里改动钩子或开新会话才生效。

### 还有一道信任门

写在 `hooks.json` 里不等于就会跑。**每条钩子声明必须在「设置 → 钩子」里被你显式信任，才会注入会话**，信任是按「作用域 + 文件路径 + 事件 + 组内位置 + 声明内容的哈希」记的。所以：

- 一条从没信任过的新声明，状态是「新钩子」，保持不执行。
- 一条你信任过、但内容之后被改动的声明，状态变成「内容已变更，需重新信任」，旧的信任作废、同样不执行——这是防的是某个技能的更新器悄悄改写它自带的钩子，然后靠你以前那一次批准继续跑代码。
- 你手动停用的声明状态是「已停用」；已经信任且内容未变的是「已信任」。

「设置 → 钩子」把钩子按来源分成三组：全局配置文件、插件、项目。每组里再按事件归拢，展开一个事件能看到每条钩子实际要跑的命令和它的状态；插件带来的钩子只显示事件和数量。可以单条信任，也可以「信任全部待审」。这也是「钩子明明写了却不跑」最常见的原因：不是事件名写错被丢，就是还没信任。另外，钩子执行失败不再往对话记录里塞内容，只写宿主日志。
- 插件带的钩子不走这条路：引擎直接从插件账本里加载它们（客户端如果也报一遍，每个插件钩子会每个事件触发两次）。
- 钩子只从 `hooks.json` 读。从其他客户端导入时，写在 `settings.json` 的 `hooks` 键里的那些只是导入来源，它们本身不会被执行。

## 偏好设置

「你自己的偏好」分散在三处：侧栏底部的头像菜单（语言、主题与配色、字号）、「设置 → 偏好设置」（编辑器 / 会话 / 应用 / 通知 / 工作区 / 配置），以及按功能分开的几页（语音、迷你助手与桌宠、联网、钩子、梦、远程控制、关于）。

- 外观：主题分「跟随系统 / 浅色 / 深色」。配色（那套代码与语法高亮色板）**浅色和深色各记一套**，所以在浅色下换过的色板不会动到深色那套；浅色有 17 套、深色有 28 套，ayu、dracula、monokai、终端绿这些只有深色有。UI 字号 11–16（默认 14），代码字号 8–24（默认 13）。
- 语言：界面和托盘立刻跟着变；同一个值还作为回复语言传给引擎——会话启动或恢复时往系统提示里追加一段指令，要求所有解释与沟通都用该语言（代码与技术名词保持原样），所以新开的会话和重新恢复的会话会带上它，正在跑的那一轮不会中途换语言。未设置时不追加任何指令，模型跟随对话本身的语言。
- 编辑器：「显示预测内容」控制输入框的消息预测（按 Tab 接受，任何模型来源都可以用，见[模型](/docs/desktop/models)）；它下面还可在「消息推荐」为预测单独指定来源和模型，默认跟随当前会话主模型。
- 会话：「后续消息行为」见下一条；「回复风格」选默认的回答风格，见[回答风格](/docs/desktop/output-styles)。
- 应用：「开机自动启动」；「运行时防止系统休眠」让电脑在 Klaus 跑任务时保持唤醒，任务结束就放开（Windows 上没有这一项）。远程控制期间的防休眠是另一个开关，在「设置 → 远程控制」，只在接着电源时生效。
- 通知：桌面通知与提示音默认都开，分别对应「需要你输入 / 干完了」和「你不在时干完了」。
- 工作区：文件树的排除规则，见[工作区、Git 与改动](/docs/desktop/workspace-git)。
- 后续消息行为：运行中发出去的消息默认「排队」（等这一轮结束再发），也可以改成「引导」（不打断模型，直接注入当前这一轮）。这只是默认值，每条消息在输入区还能单独选（⌘/Ctrl+回车取反，见[输入框与键盘](/docs/desktop/keyboard)）。
- 语音输入：识别语言默认跟随系统，转写润色和语音学习默认都开。
- 联网：搜索默认开，来源默认是 **Bing**——用后台浏览器搜，不需要 API Key，但要求浏览器插件是开的。也可以改成「模型自带」（由服务商在服务端搜，需要模型本身支持）、Codex / Qoder / 百炼 Token Plan 订阅自带的搜索，或 Brave，见[联网搜索](/docs/desktop/web-search)。关掉搜索不等于断网——你直接给网址它照样能抓。Brave 的 API Key 只能你自己填。搜索失败或撞上验证页是**明确报错**，不会静默换一家。
- 引擎运行参数：设置里已经没有单独的「运行时」页。开发调试用的 provider 痕迹开关移到了「设置 → 关于」，叫「开发调试日志」（默认关，开了之后反馈报告会带上痕迹日志路径）；最大工具并发（默认 10）没有界面，可以让 Klaus 改。主会话没有固定的模型轮数上限；子 Agent 和内部维护任务各自按任务类型设置限制。其余引擎数值不上设置面：对绝大多数人只有一个好值，就是引擎自己的默认值，而那个值会随引擎升级变化。真要调的走 `~/.klaus/config.toml`。
- 执行权限：「设置 → 偏好设置 → 配置」分别设置批准策略与沙箱模式。沙箱有「只读」「工作区写入」「完整访问权限」三种模式；工作区写入的额外可写目录、联网和临时目录规则通过 `config.toml` 中的 `sandbox_workspace_write` 配置。
- 记忆：「设置 → 梦」里的自动记录**默认关**，定期整理也默认关，详见[记忆与梦](/docs/desktop/memory)。

偏好存在两个地方。你平时不用关心，但它决定「什么时候生效」：

- `klaus.*`、`feature:*` 这些属于**引擎配置**，落在 `~/.klaus/config.toml`。一个会话的配置是它启动那一刻的快照，所以改完之后已经开着的对话会在**下一回合**自动重建并带上新值，不用重开会话。
- 外观、语言、通知这些属于客户端自己的存储，改完当场生效。
- **留空不是关掉，是回到默认**：那一行会被删掉，用的是引擎/客户端自带的默认值。所以数值和列表可以清空，开关必须明确写开或关。
- 通过偏好名称修改时会先校验值。执行权限使用配置页或 `config.toml` 中的规范配置项；旧沙箱开关和独立根目录偏好已移除。

让 Klaus 改偏好：直接说「字号调大一点」「配色换成 dracula」「关掉搜索」。它按**名字**改（`theme`、`codeThemeDark`、`uiFontSize`、`webSearch`……），不用你记存储键名，它也会先把值校验一遍。

## 输入框与键盘

键位**可以改**：「设置 → 键盘快捷键」列出全部命令，每条都能换键，两个系统级全局热键也在同一页里当普通行处理。改完原生菜单上显示的键跟着变，不用重启。下面先讲输入框里那些固定行为，再讲设置页怎么用。

### 输入框里的固定行为

这些不走命令表，也不能改：

- **发送**：Enter 发送，Shift+Enter 换行。中日韩输入法选候选词时按回车不会误发（同时看 `isComposing` 和 `keyCode 229`，因为前者在 Chromium 上按回车确认候选时常常已经变回 false）。
- **它在跑的时候你还发消息**：默认是**排队**（等这一轮结束再发出去），按住 ⌘/Ctrl 再回车则**取反**，变成**引导**（直接塞进正在跑的这一轮，不打断它）。默认值可以在偏好设置里改成引导，改了之后 ⌘/Ctrl+Enter 就反过来变成排队。以 `/` 开头的斜杠命令是例外，永远排队，不会插进正在跑的一轮。
- **消息预测**：输入框为空会显示一条预测的下一句，按 Tab 接受成草稿；任何模型来源都可以用。可以在「偏好设置 → 编辑器」关掉，见[模型](/docs/desktop/models)。
- **翻自己发过的消息**：输入框是空的时候按 ↑ 往回翻这条会话里你发过的消息，↓ 往前，Esc 回到刚才的草稿。输入框里已经有字时 ↑↓ 就是普通的移动光标，不会抢。
- **斜杠命令菜单**：打 `/` 弹出，↑↓ 选，Tab 或 Enter 补全，Esc 关掉。选中的命令在输入框里是**一个整块**，Backspace 一下删掉整条，不用一个字符一个字符退。
- **引用与添加菜单**：输入 `@` 或点击加号打开同一个菜单，继续打字即可跨来源搜索，↑↓ 选择、Enter 确认、Esc 关闭。Tab 移动焦点，不选中候选；加号不会给草稿添加触发字符。添加照片和文件会打开附件选择器，列表里的文件则插入为引用。
- **`@` 引用**同样是整块：光标停在输入框最前面时按 Backspace，会从后往前依次摘掉引用。`@` 能引用的不只文件：还有对话、设备、好友（见[好友协作](/docs/desktop/friends)），以及「标签页」——精确指向某个已经打开的浏览器标签页，让 Klaus 知道你说的是哪一页。把对话或标签页的引用链接粘贴进输入框，也会恢复成引用块。
- **弹窗**：Enter 确认、Esc 取消。多行输入的场合反过来——多行 prompt、反馈表单、规格批注里 Enter 是换行，⌘/Ctrl+Enter 才提交。
- **Esc 的通则是「关掉眼前这一层」**：命令菜单、模型选择、+ 菜单、气泡、弹窗、面板都吃 Esc。正在录音时 Esc 只用来取消录音，不会顺带把别的东西关掉。

### 排队中的消息

运行中排队的消息整齐排在输入框上方，每条都可以单独处理：

- **看全文**：悬停、聚焦或点击一条，展开完整原文，可以选中复制。
- **引导**：不等这一轮结束，立刻把这条注入正在跑的一轮，不打断模型。
- **编辑消息**：把它取回输入框，文字、图片、文件、引用和粘贴的卡片一并恢复；改完再发会回到队列里原来的位置。
- **在侧边会话中打开**：把这条连同附件与引用整个转到一条新的侧边会话里去问，不占主线。
- **调整顺序**：用鼠标拖动一条到想要的位置，向上向下拖都落在你指着的那一行。
- **删除**。

排队消息可以只带图片不写字。一条消息发出去了但没能确认是否送达时，它会留在队列里并提示「无法确认是否已送达」，这时引导、编辑和重排都暂时不可用，只能删除；重试前会让你先核对会话记录，避免同一条发两遍。

### 快捷键设置页

- 一页列全部命令，按分组排序但不画分组标题，顶上有一个常驻搜索框。搜索有两种模式：直接打字（在命令名与说明上做模糊匹配），或者切成「按键」模式——按下你想找的组合，它列出用这个键的命令，连和弦的前半段也能搜到。
- 改键：点那一行的铅笔就进入捕获，**按下的那一刻就存好了**，没有确认按钮。单击是替换，Shift+单击是再追加一个键（一条命令可以绑多个键）。Esc、点别处、或点取消退出捕获。组合键的两段式和弦会先显示「⌘K …」，等 1 秒自动提交。
- 冲突不静默覆盖：撞车时**拒绝保存**、继续捕获，在输入框下面用警告色写出「被某某命令占用」，输入框标成非法。⌘G / ⇧⌘G 是留给页内查找的，不能被绑到别的命令上，撞上去会直接以「查找」的名字拒绝你。⌘F 现在是一个普通命令键，默认打开命令菜单（会话搜索），可以改。
- 单条重置不需要确认，「全部恢复默认」需要确认一次。没绑键的命令显示「未分配」。
- 改完立刻生效，并且原生菜单项上显示的快捷键跟着改——菜单和键位是同一份数据，不会出现菜单写着 ⌘N 实际按了没反应。

### 常用的默认键位

- **会话**：⌘/Ctrl+N 新对话，⌘/Ctrl+O 打开文件夹，⌘/Ctrl+⌥R 重命名，⇧⌘/Ctrl+A 归档，⌘/Ctrl+⌥P 置顶/取消置顶。
- **导航**：⌘/Ctrl+K 或 ⌘/Ctrl+F 打开命令菜单（会话搜索；焦点在浏览器面板这类自带页内查找的地方时，⌘F 仍归它自己），⌘/Ctrl+P 搜索文件，⌘/Ctrl+1…9 切到第 N 条会话。
- **面板**：⌘/Ctrl+B 侧栏，⌘/Ctrl+J 工作面板，Ctrl+\` 终端，⇧⌘/Ctrl+E 文件面板。
- **配置**：⌘/Ctrl+, 设置，⌘/Ctrl+/ 快捷键总览（一个只读弹窗，列出当前真正生效的全部键位，包括改过的）。
- **语音**：⌘/Ctrl+⇧V 开始或停止口述。
- **系统级全局热键**（在别的应用里也生效）：⌘/Ctrl+⇧K 召唤主窗口，⌘/Ctrl+⇧Space 快速输入卡片，见[快速输入与全局热键](/docs/desktop/hotkeys)；⌥Space（Windows 上是 Win+Alt+P）显示或隐藏迷你窗口，见[迷你窗口与桌宠](/docs/desktop/desktop-pet)。

### 菜单栏（macOS）

App / File / Edit / Window 都是 macOS 标准项（Edit 下还有 Substitutions、Speech 两个系统子菜单）。View 除了重载界面、强制重载、开发者工具、全屏，还有一组面板开关（侧栏、工作面板、概览、文件、变更、浏览器、终端）——它们的快捷键就是你在设置页里改的那份。缩放是 Electron 的标准三项（恢复原始大小 / 放大 / 缩小），也就是 ⌘0、⌘+、⌘-。

**Help 菜单不是空的**：里面有命令菜单、搜索文件，以及快捷键总览那一项。Klaus 不带应用内帮助页，产品说明就是这份手册。

## 快速输入与全局热键

两个系统级热键，不管你当时在哪个应用里都能按。它们和其他快捷键一样在「设置 → 键盘快捷键」里当普通行处理，可以直接改；也可以直接让 Klaus 改（见下）。全部可改键位见[输入框与键盘](/docs/desktop/keyboard)。

- **⌘⇧K（Windows 上是 Ctrl+Shift+K）：把主窗口叫出来**。它已经在最前面了，再按一次就收起来，所以同一个键既是「找回 Klaus」也是「先放一边」；被最小化或藏起来的窗口也照样叫得回来。
- **⌘⇧Space（Ctrl+Shift+Space）：开快速输入卡片**——一行输入框浮在桌面上，写一句话回车，活就派出去了，不用先切回 Klaus 窗口。

卡片是这样的：

- 680×104 的无边框半透明小窗，浮在普通窗口之上，出现在**鼠标所在那块屏幕**上：水平居中，从可用区顶端往下 22%（可用区是去掉菜单栏 / 任务栏之后的那块）。
- 每个桌面 / Space 都看得见，也能浮在 **Klaus 自己**的全屏窗口上；但浮不进**别的应用**的全屏空间——macOS 不给浮动小窗这个能力。
- Enter 提交，Shift+Enter 只换行，Esc 关掉（正在口述时第一下 Esc 先取消录音）。**一失去焦点就消失**，而且不留字：每次召唤都是空的。
- 上限 8000 字，按 JavaScript 的算法数（一个 emoji 算两个）。空的或超了都不会提交。
- 提交之后：卡片收起、主窗口抬起，你写的那句话**开一条新会话并直接发出去**——不会掺进你上次那个对话里。要是那会儿主窗口还没就绪（冷启动），文字会被攥着等它就绪，不会丢。
- 卡片里也能口述，用的是主窗口那份麦克风权限。

改键：

- 设置页里直接改，或者直接说「把快速输入的键改成 Alt+Space」「关掉召唤热键」「热键改回默认」，Klaus 改完会**当场重新注册**，不用重启。拼法是 `CommandOrControl+Shift+K`、`Alt+Space` 这种（`CommandOrControl` 在 macOS 上是 ⌘、别处是 Ctrl）；关掉写 `off`，回默认写 `default`。
- 必须带一个真的修饰键（⌘ / Ctrl / Alt）。**Shift 不算**：`Shift+K` 注册成全局热键会把整台机器上每一个大写 K 都吃掉，所以这种写法会被拒。系统解析不了的写法也会被拒而不是存下来——存下来的后果是这个功能悄悄没了。
- **「按了没反应」通常是这个键被别的应用占了**。让 Klaus 查一下热键状态，它会分别报「设置里写的是什么」和「这个进程真正注册上的是什么」：两者不一致就是被占了，换一个键即可。注意注册失败时旧键在那之前已经解绑，所以那一刻是两边都没有键。
- Klaus 自己不能往卡片里打字提交——那等于它自己给自己开一条会话。它只能替你把卡片弹出来，而弹出来会抢走键盘焦点，所以它只在你要求时才弹。

## 系统授权

macOS 对敏感数据访问有系统级权限（TCC）。「设置 → 系统授权」集中管理这几项：

- 完全磁盘访问：信息、Safari 等连接器需要。
- 照片：照片连接器需要。
- 辅助功能与自动化：App UI、电脑操控需要。
- 屏幕录制：电脑操控的截图需要。
- 通知、定位：各自对应的小功能。

每一行显示「已授权 / 未授权 / 未知」，没有授权的行右边有一个「去授权」按钮。这个按钮做的事分两种，取决于 macOS 允许到哪一步：

- **能就地授权的**：照片、自动化、通知。点「去授权」会直接请系统弹出授权框，你当场同意，这一行立刻刷新，不用重启。
- **只能去系统设置的**：完全磁盘访问、录屏与系统录音、辅助功能、位置服务。这几项点按钮只会把对应的系统设置面板打开，勾要你自己去勾。

状态是**当场探一下**探出来的，不是读一个存下来的标记，所以它会比你记得的「我明明勾过了」更贴近真实情况；代价是有几行探不全：

- 完全磁盘访问：拿「信息」的数据库当探针，真去读一下。报权限错就是「未授权」；但如果你这台机器从没用过「信息」、那份数据库根本不存在，就只能显示「未知」——这是「我已经给了完全磁盘访问，为什么还是未知」最常见的原因。
- 自动化：向系统事件问一句，静默成功算已授权。为了让已经给过的授权真的可观测，必要时会在后台把 System Events 起一下（一个没有窗口、不进程序坞的系统代理），这一步不会弹窗打扰你。
- 辅助功能、屏幕录制：问系统框架要一个干净的布尔值，没授权时辅助功能只能知道「不是已授权」，不知道到底是没问过还是被拒了，所以显示为「未知」；录屏在系统明确拒绝时显示「未授权」，其余情况同样是「未知」。
- 照片、定位：有原生探针读得到真实状态。但定位在你从没给过时同样显示「未知」而不是「未授权」；看连接器能不能真的拉到数据比盯着这一行更准。

状态探测本身只读、不弹授权框；弹框只发生在你点上面那三项的「去授权」按钮时。页脚还有一个「刷新状态」，手动重新探一遍。

注意：macOS 会对已运行的进程缓存权限决定。在系统设置里勾选授权后，需要重启 Klaus 新权限才会生效——所以走「打开系统设置」那条路的几项，点完按钮 Klaus 就会弹出「重启 Klaus？」提示，可以选立即重启或稍后。

## 应用与更新

应用在后台自动检查更新：启动几秒后查一次，之后每 15 分钟一次。「设置 → 更新应用」提供「自动下载更新」开关（默认开启）：开启时发现新版本会在后台自动下载；关闭后发现新版本只会提示，由你点击「下载更新」时再开始传输。无论发现新版、正在下载还是下载就绪，提示都只显示在左下角侧栏底部卡片里，不会弹出居中大弹窗打断当前操作；只有下载完成并点击「重启更新」开始安装时，才会显示居中的安装进度弹窗。手动检查有三个入口：「设置 → 更新应用」页上的「检查更新」按钮、macOS 应用菜单的「Klaus → 检查更新…」、以及直接让 Klaus 去查。更新不可用（开发版、自定义数据目录等）时，原因会显示出来。

「设置 → 更新应用」这一页是版本相关事情的归口：当前版本号、手动检查/下载/安装按钮、「自动下载更新」开关，以及跳转查看历史版本更新日志的入口。它和侧栏底部更新卡片读的是同一份更新状态，所以不会出现一处说有新版本、另一处说没有。

- 更新包带 Minisign（Ed25519）签名。包下载到一个只有你能读写的私有缓存目录（`~/.klaus/electron/updates/`），下完立即验签并设为只读；确认安装时会再拉一次更新源、核对这份包仍是当前签名发布的版本，并对缓存文件重新验签一遍，之后才交给安装器。所以被篡改过的包、或已被撤下的版本都装不上。
- 确认安装后是 Klaus 自己把包换上去并重启；换失败就不重启，当前这份应用原样不动并告诉你原因。
- 自己构建或开发版本没有签名包和更新源，会直接报「不支持更新」并拒绝安装，而不是假装在检查。所以「点检查更新没反应」先看这一条。

其他应用级的事项：

- 开机自启：可以让 Klaus 随系统登录启动（守定时任务和频道消息时有用，应用没开就没人接消息）。
- 当前版本：设置页侧栏底部常驻显示（各平台一致）；macOS 上菜单栏「Klaus → 关于 Klaus」的系统面板里也有。
- 运行时能力：某个能力在这台机器上是否可用，直接问 Klaus 即可，它会读取本机的运行时能力快照回答。
- 重启：新授予的系统权限、部分引擎配置变更需要重启生效。让 Klaus 代你重启会先问你一句（重启会打断正在跑的活）。
- 看一眼当前的窗口：Klaus 能给自己的窗口拍一张截图再读图，所以「你看我这个页面」这种话它能真的看，不靠猜。

## 进程结构

「核心概念」这一组讲 Klaus 内部怎么运转。日常使用不需要了解，理解限制和排查问题时有用。

Klaus 分成两层。外壳负责窗口、界面、系统集成和一切跟 macOS 打交道的事；引擎是一个独立子进程，负责与模型对话、调用工具、维护会话。两者通过标准输入输出上的 JSON-RPC 通信。

整个应用只启动一个引擎进程，所有会话、定时任务、频道消息共用它。引擎启动后有 20 秒完成握手，超时会被回收并在界面报错，下次操作时重新拉起。一个会话对应引擎里的一条线程，会话 id 会出现在磁盘上那份会话记录的文件名里（见[数据都存在哪](/docs/desktop/data-locations)）。

一个进程承载全部会话，所以「引擎掉了怎么办」是必须回答的问题，有三层：

- **断连恢复**：连接断掉时正在跑的调用不会被永久挂着——待处理的请求会失败并报错，事件通道关闭时事件泵自己退出，客户端队列里没送出去的会重新投递。重新连上的是一个**新的一代**（generation），旧那一代迟到的事件会被按代号丢掉，不会串进新的对话里。界面上表现为侧栏那个红点：重连中，连上就消。
- **重启后自动续跑**：Klaus 自己记一份台账，写下「哪些会话在上次退出时还有没跑完的一轮」（更新重启、崩溃、你自己退出都算）。下次启动 5 秒后它读这份台账，逐条打开那些会话并接着跑没完成的那一轮，正在等的后台进程和子智能体由这一轮自己按正常工具流程重建。所以更新完重启不用你手动一条条点继续。频道消息起的会话不在这个范围里——没人在等它，重跑一遍等于重发一条消息。
- **单条会话出问题不外溢**：一条会话出错或卡住只影响它自己，其余会话照常。

## 一轮对话怎么走

1. 你发出消息。
2. 引擎组装这次请求：系统提示、项目指令文件、可用技能与子代理清单、命中的记忆、历史消息、工具清单，再加上当轮需要的提醒（最终回复风格、计划模式、记忆召回、日期变更这些）。
3. 模型返回文本，以及零到多个工具调用。
4. 每个工具调用先过权限判定（见下节），通过后执行，结果回灌给模型。
5. 只要模型还在调工具，循环继续。
6. 模型不再调工具时还有一道收尾判定，这一轮才能算结束——因为「没再调工具」并不等于「答完了」：
   - **输出被长度上限截断**：已经有可见正文但话说一半就断了，会接着让它续写，最多三次。
   - **整个预算都花在思考上、一点正文都没回来**：这种情况要「接着写」是没意义的，所以先提醒它少思考，最多两次；梯子用完了就**停下来问你**要不要重试，而不是默默收一个什么也没产出的回合。
   - **已经干出了活、收尾却回了个空响应**：先重试一次（网关抢一下或模型忘了收尾都能救回来）；还不行就把这一轮判为失败，而不是当作完成——活没干完的回合默默标成完成，看上去就像它自己停手不干了。
   - 工具调用的**参数**被截断是另一种情况：那个调用根本没执行，修法是给它更大的输出预算让它重发，不是续写。

界面上的正文、工具卡片、完整计划、进度清单、压缩提示和记忆提示，都是引擎推送的独立事件。计划模式与工具权限独立：模式在请求边界确定，完整提案与执行时的 `update_plan` 清单分别显示；结构化问题的回答只回到发起它的会话和调用。

有活动目标时，这轮结束后还要经过目标续跑判定。引擎先处理用户输入和其他待处理工作，只在执行模式下的安全空闲点继续。每次续跑有自己的回合和计量；暂停、停止、额度/预算限制或目标清除会阻止不适当的续跑。目标完成需要实际验证和最终记账，不能把一次普通回合结束当作达成，详见[目标与侧任务](/docs/desktop/goals)。

## 权限是怎么判的

普通、项目、工作区、好友和定时任务会话共用同一套执行权限。会话类型只影响初始化的默认目录和权限，不额外叠加一层目录沙箱。每个聊天保存自己的权限选择；运行中修改后，从下一次工具调用开始生效，重建会话也保留这份选择。

计划模式是独立的会话模式，不是第四个权限档。接受计划后，具体操作仍按当前执行权限判断。

### 默认目录

- 普通会话以自己的工作目录为默认可写目录。
- 项目会话以项目目录为默认可写目录。
- 工作区会话包含该工作区保存的全部目录，首个目录作为工作目录。
- 好友会话以该好友自己的共享子目录为基础，再加入所选项目、工作区和额外设置的可写目录。
- 定时任务选择普通会话、项目或工作区后，按相同规则初始化。

这些目录决定哪些普通写入可以直接执行，不是所有读取的绝对边界。普通只读操作可能直接读取目录之外的文件；显式规则、工具自身检查和操作系统权限仍然生效。

### 三档权限

- **请求批准**：默认可写目录内的普通文件编辑和沙箱命令直接执行；范围外写入、需要提升权限或联网的操作进入批准流程。敏感文件和明确要求审核的操作仍可能需要确认。
- **帮我批准**：使用当前沙箱和默认可写目录；需要批准的操作交给独立审核智能体判断，审核可能批准、拒绝或交给你处理。
- **完全访问权限**：解除普通目录沙箱并关闭普通批准提示。好友和定时任务也采用同一含义，不再保留专用目录硬边界。操作系统本身没有授予的权限不会因此出现，明确拒绝的规则仍然有效。

权限允许后，工具仍需实际执行成功。文件不存在、系统拒绝访问、应用未授权和工具参数错误，都不能靠切换权限档解决。

### 初始化与后续修改

好友设置中的执行权限只作为新好友会话的初始选择。接收任务的方式决定是否接收这次请求，与运行中的工具批准是两件事。Computer Use 的应用授权独立管理。

定时任务保存自己的执行位置和三档权限。每次运行创建普通执行会话并以任务保存的选择初始化；旧任务保留原有的完全访问默认值。选择请求批准时，需要批准的操作会在该次运行的会话中等待你处理；选择帮我批准时进入相同的审核流程。调度器不会因为任务在后台就把它提升到完全访问。运行中改档只改变这次会话，任务表单的保存值决定下一次运行。

## 上下文与自动压缩

模型每次请求能装的内容有上限，Klaus 的算法是：

- 有效窗口 = 模型上下文窗口 − 输出预留（窗口默认按 20 万 token 算，预留默认 2 万，且预留不超过模型允许的单次输出上限）。
- 压缩触发线 = 有效窗口 − 1.3 万 token 的绝对预留。留绝对量而不是百分比，是因为触发时要腾出的东西（这一轮的回复加摘要请求本身）是固定开销，窗口再大也不会变多；按比例留会让大窗口白白浪费掉几十万 token。
- 到线：历史被换成摘要，对话继续。

**按占用触发的默认只有「到线」这一档**，而这一次是要等的——长会话跑到某个点忽然卡一下再继续，那一下就是它。另外还有三级提前动作，界面上都没有开关（只能改引擎配置）；前两级默认关着，第三级默认开着：

- 提前轻量清理：到了「触发线 − 有效窗口的 15%」就丢掉早期工具输出的正文。清理后必须降到「触发线 − 有效窗口的 5%」才算够，否则还是升级为完整压缩。
- 后台预先摘要：到了「触发线 − 有效窗口的 7%」就在后台先把摘要算出来，真到线时不必阻塞等待。
- 空闲期微清理（默认开）：一条会话冷下来超过 60 分钟再发下一条时，先把旧的工具结果清掉（保留最近 5 条原文）。间隔阈值按各家供应商最长的提示缓存寿命取，所以这一下永远不会造成一次本来不会发生的缓存未命中。

输入区旁那个上下文用量圆饼对应三档：正常、达到触发线 85% 显示接近上限、到线显示超限。

### 两个熔断

压缩反复失败或反复白做都是真实的坑，所以除了上面的阈值还有两道保护：

- **没进展就熔断**：一次压缩只有在把占用降到原来的 99% 以下才算「真降了」——清掉一个本来就很小的结果这种毛毛雨不算。连续三次压缩都没有实质进展，熔断器跳闸，不再白耗模型调用。
- **快速回填抖动熔断**：另一种失败形态是压缩确实成功了（真的腾出了 token，所以上一道熔断不会跳），但上下文在两三轮内又爬回触发线——因为同一个超大输入（一个巨大的文件、一个巨大的工具结果）在被反复读。一次压缩必须「按住」上下文低于线三轮才算健康，没按住就是一次快速回填；连着三次跳闸，回合带一个可补救的错误停下来，而不是把整轮预算烧在背靠背的压缩上。

## 记忆是怎么长出来的

记忆是本机 `~/.klaus/agent-memory` 下的一组 Markdown 文件：`MEMORY.md` 是索引（界面上叫「记忆目录」），每条记忆是一个独立的 `.md`，文件名的前缀就是它的分类：`user_*`（关于你）、`feedback_*`（你的偏好）、`project_*`（在做的事）、`reference_*`（相关资料）。不带这四个前缀的文件界面上直接显示文件名。

写入有两条路：

- 做梦：默认关闭。打开后，累计 ≥ 5 个新会话且距上次做梦满 24 小时时在后台跑一次，把近期会话里值得留的东西整理进记忆文件。也可以在记忆页手动触发（手动不看这两个阈值）。一旦开始就不能中止。
- 每轮保存：默认关闭。打开后每轮对话结束就直接写。

两个开关都默认关着，所以全新安装的 Klaus 并不会自己长记忆：想要「随手记」先开第一个，想要「收拢成册」再开第二个。做梦是把零散记忆收拢成册的动作，不是开关本身的替代品。

因为记忆就是普通文本文件，你可以在 Finder 里直接打开改或删。

## 扩展怎么被加载

- 技能：先看当前项目的 `<项目>/.klaus/skills`，再看 `~/.klaus/skills`，同名先到先得，也就是项目里的同名技能会盖住全局的。内置技能只在名字还没被占用时补进来。
- 子代理：`~/.klaus/agents/*.md`。
- 斜杠命令：全局 `~/.klaus/commands`，项目 `<项目>/.klaus/commands`。
- 回答风格：全局 `~/.klaus/output-styles`，再从会话工作目录往上逐级找各级 `.klaus/output-styles`（到仓库边界为止），同名后者盖前者。
- 钩子：全局 `~/.klaus/hooks.json`，项目 `<项目>/.klaus/hooks.json`，且每条声明要先在设置里被信任才注入会话，见[钩子](/docs/desktop/hooks)。
- 插件：由引擎自己读它配置里的插件账本加载，见[插件](/docs/desktop/plugins)。插件里带的技能、命令、子代理、MCP、钩子会打上来源标记，不会和上面几类重复出现。插件启停是应用级的，没有项目作用域。

### 改完什么时候生效

这里有两条不同的路径，混在一起说就会给出错答案：

- **在 App 里改**（从市场装技能、启停插件、在钩子页点信任）：客户端知道这件事变了，会把已经开着的会话标记为「配置过期」，于是在**下一回合之间自动重建**并带上新值。不用重开会话，更不用重启应用。插件尤其如此——装完、启用、停用都免重启。
- **手动改磁盘上的文件**（自己在编辑器里改 `hooks.json`、往 `.klaus/skills` 丢一个目录）：Klaus **不监听**这些目录，所以没人告诉它变了。这些内容在会话启动时读取，改完要开一个新会话才生效。

所以「装完新技能要开新会话」这句话只对第二种情况成立。真在界面上装的东西，下一轮就带上了。

## 定时任务怎么被调度

到点时 Klaus 起一个独立会话执行任务提示词，跑完结束。任务保存的普通会话、项目或工作区选择决定初始目录，保存的三档权限决定是否请求你批准、交给审核智能体，或采用完全访问。运行时与普通会话共用同一套机制；旧任务保留原有的完全访问默认值。任务里选的模型和思考档会被带进这个会话，不跟随你在输入框里的全局选择。

单次运行超时默认 5 分钟；如果任务自带了「超时秒数」，调度器就用那个值，上限 24 小时。进程在运行途中意外退出时，那些卡在「运行中」的记录会在下次启动时被立即标为失败（标成「interrupted (app restart)」），不会永远转圈；另有一道兵底会回收超过 24 小时仍未收尾的 running 行。调度与投递日志写在 `~/.klaus/electron-host.log`，是其中 `kind` 为 `cron` 的那些行。

## 频道消息怎么进来

一条外部消息进入 Klaus 要过这几步：

1. 去重：平台重复投递的同一条消息直接丢弃，连「收到」都不记，否则日志会显示根本没发生过的流量。
2. 门禁：按私聊/群聊策略、白名单、群里是否被 @ 判断要不要处理。被挡掉的消息对发送者是静默的，不会回一句「你没权限」。
3. 认主：某个平台上第一个私聊你的账号被记为主人，只记一次。桌面端无法自己知道你在每个 IM 上的身份，所以以首次私聊为准。
4. 绑定上下文：把频道、账号、来源会话、目标会话、私聊还是群聊记进这次会话，任务和工具因此知道该把结果发回哪。
5. 交给引擎处理，回复沿原路发回该平台。

## 数据都存在哪

全部在 `~/.klaus/` 下：

- `settings.db`：设置与本地状态（SQLite，WAL 模式）。
- `sessions/`：这一个目录装了两样东西——会话记录是 `<创建时间戳>-<会话 id>.jsonl`（所以按文件名排序就是按时间排序，找某个会话搜它的 id）；同名的**目录**则是那个会话的工作区，只有你没给它指定项目目录时才会用到，另外 `__klaus__` 是没有项目时共用的那个锚点目录。
- `projects/<工作目录路径，斜杠换成横线>/`：按项目分的项目级记忆（`memory/` 子目录）。会话元信息不再单独落一个 sidecar 文件，而是写在会话记录（jsonl）的头部。所以「同一个项目下的历史会话」是靠工作目录路径归拢的，换了目录名就换了一堆。
- `agent-memory/`：记忆文件。
- `skills/`、`agents/`、`commands/`、`plugins/`：全局技能、子代理、斜杠命令、插件。（插件的安装账本本身不在这个目录，而在 `config.toml` 的 `[plugins]` 段，见[插件](/docs/desktop/plugins)。）
- `visualizations/<会话 id>/`：每个会话一个目录，装它的内联可视化页面。它既是这些页面的可写根，也是预览白名单根，所以只有本会话的页面能被渲染。
- `friends/<好友关系 id>/`：每个好友的共享子目录，这个好友派来的任务以它为基础目录，见[好友协作](/docs/desktop/friends)。
- `pets/`：自己导入或创建的桌宠（精灵图加 `pet.json`），见[迷你窗口与桌宠](/docs/desktop/desktop-pet)。
- `checkpoints/<项目指纹>/`：文件检查点的**影子 git 仓库**。工作树指着你的项目，历史却落在这里，所以你自己的 `.git`、分支、暂存区完全不被碰（这个能力默认关着，见[主界面与会话](/docs/desktop/sessions)）。
- `channels/<平台>/access.json`：每个频道的门禁配置，详见[频道](/docs/desktop/channels)。
- `electron/`：桌面端的运行时数据，包括重启后自动恢复任务的台账 `resume-ledger.json`。
- 日志：桌面端宿主的诊断都写进 `electron-host.log`，每行一条 JSON，用 `kind` 字段区分来源——定时任务的调度与投递是 `cron`，做梦与记忆维护是 `memory-maintenance`，频道启动失败是 `channel-failed` / `channel-startup`，重启后自动续跑是 `resume-recovery`（文件超过 10 MB 时在下次启动改名为 `electron-host.log.previous`）。`logs/` 下另有分项日志：频道收发 `channel-activity.jsonl`、MCP 诊断 `mcp-diagnose-*.log`，以及模型请求的 `provider-*.log`。旧版本留下的 `cron.log`、`memory-maintenance.log` 已不再写入。桌面应用的输出到不了启动它的终端，所以这些机制一律自己写文件——排查时直接看对应那一份，比翻控制台有用。

设置本身有两个来源：大多数开关与面板状态是 `settings.db` 里的键值行，没写过的键不存行——所以「查不到这个设置」通常意思是它还是默认值，而不是被清空了；引擎侧的配置则落在 `~/.klaus/config.toml`（引擎自己读这份文件），界面上没摆出来的引擎开关、插件账本、市场目录登记、信任记录都在那里。API Key、配对令牌这类凭据也存在这里，但不会交给模型：Klaus 自己读设置时凭据字段一律是遮蔽后的值。

从别的客户端导进来的会话记录写进 `~/.klaus/sessions/`（引擎的会话存储目录），不在 `projects/` 下；导入时没指定项目归属的，还会在 `sessions/<会话 id>/` 建一个工作区目录。

删掉 `~/.klaus` 等于把 Klaus 恢复到初装状态，登录、设置、会话、记忆一并消失。

## 排障与 FAQ

**日志在哪里？** 都在 `~/.klaus/` 下：桌面端的诊断写在 `electron-host.log`，每行一条 JSON，按 `kind` 字段找——定时任务是 `cron`，做梦与记忆维护是 `memory-maintenance`；MCP 诊断和频道收发在 `logs/` 里。反馈问题时附上相关片段有助于定位（应用内反馈会自动带上会话信息，不用自己贴）。

**我的数据存在哪里？** 会话、设置、记忆等本地数据都在 `~/.klaus/` 目录下。

**连接器打不开 / 一直显示需要授权？** 先在「设置 → 系统授权」或 macOS 系统设置中完成对应授权，然后重启 Klaus——不重启不生效。

**定时任务没有触发？** 依次检查：任务是否处于启用状态；下次运行时间是否符合预期（注意时区）；任务详情里的运行历史，以及 `~/.klaus/electron-host.log` 中该时间点 `kind` 为 `cron` 的记录。单次运行默认 5 分钟超时，任务自带的「超时秒数」会被采用（上限 24 小时），跑得久的任务要把这个值调大。进程在运行途中退出（更新重启、崩溃），那些卡在「运行中」的记录会在下次启动时被标为失败。

**Klaus 一直没做梦？** 自动做梦默认是关的，先去「设置 → 梦」打开；打开之后还要同时满足两个条件才会跑：距上次做梦满 24 小时，且累计 ≥ 5 个新会话。不想等就在记忆页手动「现在做一场梦」，手动触发不看这两个门槛，但同样要求那个开关是开着的，并且本次启动以来至少有一条会话跑完过一轮。（顺带一提，同一页那个「自动记录」开关也是默认关的，不开的话 Klaus 不会随手记东西。）

**钩子写了却不跑？** 两个最常见的原因：事件名写错的条目会被直接丢掉（不报错）；或者那条钩子声明还没在「设置 → 钩子」里被信任——新声明和内容变过的声明一律不执行，见[钩子](/docs/desktop/hooks)。

**为什么改了 MCP / 项目配置没生效？** 分两种：在 App 里改的（市场装技能、启停插件、钩子页点信任）会把已开着的会话标为过期，下一回合之间自动重建带上新值，不用重开；但你自己在编辑器里改磁盘文件的不行——Klaus 不监听这些目录，得开一个新会话才读得到。见[扩展怎么被加载](/docs/desktop/extension-loading)。

**能让 Klaus 自己去改设置、建任务、装技能吗？** 能，直接说就行。读取类的它直接做，不可逆的动作会先问你，需要主人单独确认的控制接口，后台定时运行不能替主人确认。见[让 Klaus 操作 Klaus](/docs/desktop/self-operation)。

**Klaus 自己了解自己吗？** 本手册随应用内置，Klaus 可以直接检索它，所以关于产品行为、开关含义、内部机制的问题都可以直接问。

**如何反馈问题？** 每条会话的 ⋯ 菜单里有「报告问题」，会自动带上会话上下文；或者邮件 support@klaus-ai.cn。提想法（建议）窗口里没有入口，直接跟 Klaus 说让它替你提交，见[反馈与建议](/docs/desktop/feedback)。

## Klaus iOS

### Klaus iOS 概览

Klaus iOS 是 Klaus 的 iPhone 远程客户端。它让你离开电脑后继续查看和控制桌面端会话：切换设备与项目、打开会话、发送消息和附件、查看回复与执行状态，以及处理任务中的确认。

手机端不会在 iPhone 上启动 Klaus 引擎，也不会直接读取电脑文件。文件、命令、模型调用和工具执行始终发生在你选中的桌面端；iOS 端负责把操作送过去，再把会话状态和结果同步回来。

#### 连接方式

手机和电脑登录同一个 Klaus 账号后，iOS 会自动发现已经允许远程控制的桌面端。不需要扫码、局域网配对或手动填写令牌，也不要求两台设备连在同一个网络里。

桌面端是否可被看见，由那台电脑上的「设置 → 远程控制 → 允许远程控制这台设备」开关决定：

- 开启：电脑加入账号设备列表，可以被 Klaus iOS 远程控制。
- 关闭：电脑从设备列表移除，不再接受移动端连接。

#### 目前可以做什么

- 查看同一账号下允许远程控制的桌面设备及在线状态。
- 按设备浏览项目与会话，新建或继续桌面端会话。
- 发送文字、图片和文件，查看回复、工具进度和任务状态。
- 停止正在运行的任务，并处理桌面端发来的权限确认。
- 管理设备列表；移除设备时，目标桌面端会退出 Klaus 账号。
- 在手机端切换语言、主题，以及桌面端已开放的模型和运行设置。

#### 使用前提

1. iPhone 已通过 TestFlight 安装 Klaus iOS。当前尚未开放 App Store 公开下载。
2. 电脑已安装并运行 Klaus 桌面端。
3. 手机与电脑登录同一个 Klaus 账号。
4. 桌面端已开启「允许远程控制这台设备」，并保持联网。

第一次连接照[开始使用](/docs/ios/getting-started)操作；想了解移动端与桌面端各自负责什么，见[远程控制会话](/docs/ios/remote-control)。

### 开始使用 Klaus iOS

#### 安装与登录

Klaus iOS 当前通过 TestFlight 内测分发。获得测试资格后，在 iPhone 上用 TestFlight 安装或更新 Klaus，然后打开应用。

登录页支持三种方式：

- 邮箱和密码；
- Google；
- GitHub。

选择与桌面端相同的 Klaus 账号。这里的 Klaus 账号用于识别你的设备和会话；它与 Claude、ChatGPT/Codex、Qoder 等模型来源的订阅登录不是一回事。

#### 在电脑上允许远程控制

在要连接的电脑上：

1. 打开 Klaus 桌面端并登录同一个 Klaus 账号。
2. 进入「设置 → 远程控制」。
3. 开启「允许远程控制这台设备」。
4. 保持 Klaus 运行并联网。

开关打开后，这台电脑会加入账号设备列表。回到 iPhone，刷新设备列表或点「重新连接所有设备」，通常不需要重新登录。

#### 开始一段远程会话

1. 在 iPhone 的设备列表里选择一台在线电脑。
2. 从项目或对话中打开已有会话；也可以在当前桌面端新建会话。
3. 输入消息并发送。任务会在所选电脑上执行，回复与工具状态同步显示在手机上。
4. 如果任务需要权限确认，直接在手机上处理；需要停下时使用停止操作。

设备显示离线时，历史会话仍可能出现在列表里，但新的操作需要等桌面端重新在线。常见连接问题见[故障排查](/docs/ios/troubleshooting)。

### 远程控制会话

#### 一次操作怎么走

你在 iPhone 上发送消息后，Klaus 会把它交给当前选中的桌面端会话。桌面端的引擎读取项目上下文、调用模型和工具，再把过程与结果同步回手机。

因此远程使用时有两条边界：

- 手机退出或锁屏，不会把已经交给桌面端的任务搬到手机执行；桌面端仍按自身状态继续。
- 桌面端退出、断网或关闭远程控制后，手机不能发起新的操作，直到那台设备恢复在线并重新允许连接。

#### 会话与项目

设备范围决定你正在看哪台电脑的数据。选择「全部设备」可以汇总查看账号中的会话；选择某台设备后，新会话和操作会发往那台电脑。

手机端可以浏览桌面端已有项目、打开会话、创建新会话，以及对可管理的会话执行重命名、删除、导出和生成调试报告等操作。项目目录本身仍由桌面端持有，iPhone 不会获得对那个目录的直接文件访问。会话里派出去的子智能体，其转录也能在手机上展开看。

一个边界说清楚：「一个对话派活给另一个对话」这类会话间通讯目前只在桌面端有入口，iPhone 上看到的是它们跑出来的结果，不是在手机上发起它们。

#### 消息、附件与任务状态

- 文字消息进入当前桌面会话。
- 图片和文件会作为当前消息的附件发送给桌面端处理。
- 运行中的回复、工具调用和状态会持续同步到手机。
- 需要确认的权限请求会显示在会话中，可在手机端允许或拒绝。
- Klaus 反过来问你东西时（弹一个带选项或输入框的追问卡），用的是同一套交互：在手机上选、填、提交，或直接关掉让它别问了。
- 使用停止操作会请求桌面端中止当前任务。

网络暂时中断时，应用会尝试重新连接。界面明确显示离线或连接不稳定时，不要重复发送同一条请求；先重连并确认会话状态，避免任务恢复后收到重复指令。

### 设备与访问管理

账号设备列表只展示已经允许远程控制的桌面端。在线状态来自对应电脑，用户不需要管理 Relay 地址、配对码或连接令牌。

列表里显示的名字默认是电脑自己报上来的，但**可以改**：在那台电脑的「设置 → 远程控制」里给它起一个你认得出的名字（比如「公司 Mac」「卧室那台」）。改过的名字优先，而且不会被电脑每 20 秒一次的心跳刷回去。iPhone 端只读显示这个名字，改名要去桌面端做——同账号有多台电脑时，这一步能省去「到底连的是哪一台」的猜测。

#### 允许或禁止一台电脑被控制

在桌面端「设置 → 远程控制」里使用「允许远程控制这台设备」开关：

- 开启后，这台电脑注册到账号设备列表，并接受同一 Klaus 账号下的移动端连接。
- 关闭后，这台电脑从设备列表移除，现有移动端连接会结束。

这个开关只决定远程访问，不会退出桌面端账号，也不会删除本地会话。

#### 在线状态

- 在线：桌面端正在运行、联网并保持远程控制开启，可以接收操作。
- 连接中或重连中：手机正在恢复连接，可以手动点「重连」。
- 离线：账号仍认识这台设备，但当前不能执行新的远程操作。

#### 移除设备

在 iPhone 的设备列表中对目标设备点「移除」并确认。移除不是简单隐藏：目标桌面端会退出 Klaus 账号，服务端设备记录也会删除。那台电脑上的本地项目和会话文件不会因此被抹掉；以后要再次远程使用，需要在桌面端重新登录并重新开启远程控制。

移除操作适合处理不再使用、丢失或不应继续访问账号的电脑。只是暂时不想被手机控制时，在那台电脑上关闭远程控制开关即可。

### Klaus iOS 故障排查

#### 登录页打不开或第三方登录失败

先确认 Safari 能正常打开 `https://klaus-ai.cn`，再在 Wi-Fi 与蜂窝网络之间切换重试。Google 和 GitHub 登录需要能访问对应服务；如果网络环境拦截或中断认证页，可以改用 Klaus 邮箱和密码登录。

系统时间明显不准也会导致 HTTPS 证书校验失败，先打开 iOS 的自动设置日期与时间。认证完成后如果应用没有自动返回，关闭认证页再重新发起一次，不要连续叠加多个登录窗口。

#### 已登录，但没有任何桌面设备

按顺序检查：

1. 手机与电脑是否登录同一个 Klaus 账号，而不是只登录了相同的模型订阅。
2. 桌面端是否正在运行并联网。
3. 桌面端「设置 → 远程控制 → 允许远程控制这台设备」是否开启。
4. iPhone 上点「重新连接所有设备」或刷新设备列表。

如果桌面端刚切换账号，先等旧连接结束，再确认开关仍然开启。

#### 设备显示离线或一直重连

确认电脑没有休眠、退出 Klaus 或切断网络。然后在手机的设备列表里对这台电脑点「重连」。仍未恢复时，在桌面端关闭再开启一次远程控制，让设备重新登记。

VPN、代理或公司网络可能会中断长连接。可以分别用蜂窝网络和普通 Wi-Fi 测试，以判断问题发生在手机网络还是电脑网络；无需让两台设备进入同一个局域网。

#### 消息发出后没有继续

先看当前选中的设备是否仍在线，以及会话里是否停在权限确认。桌面端被锁屏、休眠或关闭后，已经显示的历史不会消失，但新消息无法执行。连接恢复后再发送一次；不确定上一条是否到达时，先查看会话末尾，避免重复下达同一任务。

问题仍无法定位时，在可管理的会话菜单中生成调试报告，再通过 `support@klaus-ai.cn` 联系支持。

## Klaus Cli

### 概览

Klaus Cli 是同一个引擎的另一个入口，可执行文件叫 `klaus`。它和桌面应用 Klaus 读同一套配置、技能、插件与 MCP 服务器，所以在 Klaus 里配好的东西在终端里直接可用，反之亦然。

它面向习惯待在终端里的人。用法是对话式的：你用自然语言说要做什么，Klaus 自己决定读哪些文件、调哪些工具、跑哪些命令，并在关键操作前按权限设置向你确认。

#### 核心能力

**读改代码**

- 跨文件理解项目结构与依赖，在真实工作目录里改。
- 描述一个缺陷让它定位并修，或者把一段逻辑抽出来重构。
- 用 `klaus review` 审改动：默认审工作区未提交的部分，也可以指定基线分支、某个 commit 或具体文件。

**接外部能力**

- 通过 MCP 接入外部服务与自定义工具，`klaus mcp` 还能不经模型直接点名调用某个工具，用来验配置通不通。
- 技能、插件、子代理、钩子与桌面端共用同一批文件，装一次两端都有。

**串进自动化**

- `klaus exec` 跑完即退，退出码反映结果，可以直接写进脚本与 CI。
- `--json` 输出引擎的原始协议，一行一个值，诊断信息走 stderr，stdout 可以当纯数据管。

#### 运行机制

核心是一个 agent 循环：接你的请求、规划步骤、调用工具、根据结果决定下一步。四个要素协同：

- **引擎**：理解意图、规划、决定下一个动作。一个会话对应引擎里的一条线程。
- **工具**：它与项目和环境交互的手段，读写文件、执行命令、搜索代码、抓网页。
- **权限**：有副作用的动作按规则决定放行、询问还是拒绝，规则和桌面端是同一份。
- **上下文**：对话历史、项目指令文件、命中的记忆和工具结果共同构成它的背景信息，接近窗口上限时自动压缩。

想深入看这套机制，见[一轮对话怎么走](/docs/desktop/turn-lifecycle)与[权限是怎么判的](/docs/desktop/permission-resolution)。

#### 几种工作方式

同一件事有不同的做法：

- **交互会话**：直接跑 `klaus`，一行一轮，最常用。回合进行中输入的一行会被送进当前这一轮而不是排队。
- **一次性执行**：`klaus exec "…"`，跑完就退，适合脚本与 CI。
- **问一句不留痕**：`klaus ask`，不写进会话历史，适合查东西。
- **审代码**：`klaus review`，产出带位置的结构化发现。
- **驱动已有引擎**：`--remote ws://主机:端口` 配合 `klaus serve`，不在本进程里另起一个引擎。

#### 适用场景

- **不想离开终端**：编辑器、shell、git 都在一个窗口里，任务也在这里发起。
- **只有 SSH 的机器**：远端服务器上没有图形界面，命令行是唯一入口。
- **串进流水线**：在 CI 里以非交互方式跑，用退出码和 `--json` 消费结果。
- **验 MCP 配置**：不经模型直接调用工具，确认服务器和参数是对的。
- **批量重复的活**：写成脚本循环调 `klaus exec`，比在界面里一遍遍点更省。

### 安装

macOS（Apple Silicon）：

```
curl -fsSL https://klaus-ai.cn/install.sh | sh
```

Windows（x64，在 cmd 里跑）：

```
curl -fsSLo install.bat https://klaus-ai.cn/install.bat && install.bat
```

当前发布的版本、平台和体积在 https://klaus-ai.cn/cli 上；那一页显示的是服务端此刻真实有的产物，比这里的描述更准。安装脚本的行为：

- 先识别系统与架构，再去读发布清单。当前仅支持 macOS Apple Silicon 与 Windows x64；其他平台会在下载前直接停止并给出 Klaus 桌面应用的下载地址，不会装到一半失败。
- 下载后比对 sha256，不一致就中止，且不写入任何文件。
- 只装到用户目录：macOS 是 `~/.klaus/bin`，Windows 是 `%LOCALAPPDATA%\Klaus\bin`。不需要 sudo 或管理员权限。
- 目录不在 PATH 上时，脚本会把那一行写进你的 shell 配置文件（`.zshrc` / `.bash_profile` / `config.fish` / `.profile` 里它在的那个），写完提示开一个新终端。这么改是因为「跑完官方一行命令然后敲 `klaus` 却得到 command not found」比改一行配置更糟。已经写过就不重复写，所以重跑是无操作；不想让它碰你的配置文件，跑之前设 `KLAUS_NO_MODIFY_PATH=1`，它就只打印该怎么加。Windows 那边是写用户级 PATH，同样对新开的窗口才生效。
- 脚本本身是纯文本，可以先用浏览器打开 https://klaus-ai.cn/install.sh 读完再决定要不要执行。

重装同一条命令即可，会原地替换成新版本。装到别处用 `KLAUS_INSTALL_DIR` 指定目录。

### 日常用法

不带子命令直接运行就进入交互会话，一行一轮：

```
klaus
```

会话里的键与斜杠命令：`/help` 列出全部；`/model <id>` 和 `/mode <模式>` 从下一轮开始换模型或权限模式；`/config model=... mode=...` 一次改两个并回报实际生效的值；`/exit` 或 ctrl-d 离开。ctrl-c 打断正在跑的这一轮，在空提示符上连按两次才退出。回合进行中输入的一行会被送进当前这一轮（steering），而不是排到下一轮。

跑完就退的用法，退出码反映结果，可以直接串进脚本：

```
klaus exec "把这个函数拆开"
```

其他常用子命令：

- `klaus ask <问题>`：问一句但不写进会话历史，适合查东西。
- `klaus review`：审代码。默认审工作区未提交的改动，也可以对某个基线分支、某个 commit、指定文件或自由指令审，产出带位置的结构化发现。
- `klaus mcp`：管 MCP 服务器，也能不经模型直接点名调用某个工具、读某个资源、取服务器自带的 prompt 模板——用来验「这台服务器到底通不通、参数对不对」。
- `klaus session`、`klaus history`、`klaus rewind`、`klaus compact`：会话的列出、看历史、撤回若干轮（可连带撤回文件改动）、压缩上下文。
- `klaus cost`、`klaus context`：这个会话花了多少、上下文窗口占用多少。
- `klaus skill`、`klaus plugin`、`klaus agent`、`klaus hook`、`klaus memory`、`klaus task`：与 Klaus 各设置页对应的命令行入口。
- `klaus engine`：端点级的东西——配置文件、钩子文件、持久权限规则、凭据。这些不属于任何一个会话，所以这组命令不会开会话（读配置不依赖一个「由这份配置来配置」的会话）。
- `klaus capabilities`、`klaus extensions`：排障用——当前会话实际解析出的运行时能力、实际生效的扩展图（技能、子代理、钩子、MCP）。
- `klaus completion <shell>`：生成 shell 补全脚本。

### 全局选项

这些选项在会话建立时固定，所以放在子命令之前，之后无法中途更改：

- `-C, --cd <目录>`：会话的工作目录，默认当前目录。
- `-m, --model <id>`：本次会话用哪个模型。
- `-p, --permission-mode <模式>`：会话启动时的权限模式。
- `--json`：输出引擎的原始协议 JSON，一行一个值。这是给程序读的形态——读到的就是引擎说的原话，不是命令行自己包装的一层。诊断信息一律走 stderr，所以 stdout 可以当纯数据管。
- `--remote ws://主机:端口`：驱动一个已经在跑的引擎，而不是在本进程里起一个。配合 `klaus serve` 用。
- `--config-json <JSON>`：直接给一段引擎配置，优先级低于上面这些具名选项。
- `--resume <会话 id>`：接回一条已经存下来的会话，而不是新开一条。`--fork <会话 id>` 是另一回事：拿那条会话的历史做种子、另起一条新的，原来那条不动（两者不能同时给）。
- `--provider <名字>`：模型后端（anthropic 默认、openai、gemini）。选后端是引擎端点自己的事，所以用 `--remote` 驱动别人的引擎时这个选项不能用。
- `--goal-mode`：开目标模式——目标工具，加上每轮结束后自动接着跑。引擎里默认关着，因为自动续跑会在你没再开口的时候就花 token，所以要逐会话显式要。
- `--token <TOKEN>`：`--remote` 的 bearer token，只能配 `--remote` 用。
- `--session-dir <目录>`：会话记录写到哪。不指定就是 `~/.klaus/sessions`，所以 CLI 里开的会话在桌面端也能看到。
- `--no-discovery`：这一跑不从磁盘读技能、子代理、钩子和 MCP 服务器。`--no-plugins` 只跳已安装插件的加载，其他三类照读。
- `--skills-dir <目录>` / `--agents-dir <目录>`：额外加一个技能或子代理目录，可重复给，排在标准根之后搜。
- `--plugin-home <目录>`：引擎读插件账本的目录。

### 与 Klaus 的关系

两者是同一个引擎的两个客户端，都只通过引擎对外声明的具名方法接入，不存在只有其中一个能用的引擎能力。用户级的配置、技能、钩子与 MCP 服务器都在 `~/.klaus` 下，项目级的在 `<项目目录>/.klaus` 下，两端读的是同一批文件（同名时项目级覆盖用户级）。会话记录默认也落在 `~/.klaus/sessions`，所以 Klaus Cli 里开的会话在 Klaus 里能看到。Klaus 独有的是需要图形界面的部分（浏览器面板、语音输入、系统托盘、窗口截图）；Klaus Cli 独有的是能被管道和退出码消费（`--json`、`klaus exec` 串脚本）。

### 常见问题

- 装完提示 `command not found: klaus`：安装脚本已经把安装目录写进你的 shell 配置了，只是**已经开着的那个窗口不会自己重读**。开一个新终端通常就好了。Windows 同理，`setx` 写的 PATH 对已经开着的窗口不生效。如果当初是用 `KLAUS_NO_MODIFY_PATH=1` 装的、或脚本写不进去，就按它最后打印的那行自己加进 shell 配置；赶时间可以直接用全路径 `~/.klaus/bin/klaus`。
- 提示平台不受支持：目前仅支持 macOS Apple Silicon 与 Windows x64，其他平台会在下载前直接停止，不会安装无法运行的产物。
- 校验和不匹配：下载被损坏或被篡改，此时脚本不会安装任何文件。重试一次；仍然不匹配就不要绕过它。
- 想升级：重新跑一次安装命令。
